## 项目代码里已发现的真实缺陷（教学素材，也是他答辩会被问的点）

### 缺陷 1　`Book` 带参构造忽略了 `isBorrowed` 参数
`Book.cpp:18-27`：
```cpp
Book::Book(string title, ..., double price, bool isBorrowed)
{
    ...
    m_isBorrowed = false;      // ← 传进来的 isBorrowed 被丢掉了
}
```
后果：创建一本"已借出"的书，实际得到"可借"。这是**形参和实参脱节**的典型，讲构造函数那章要挖出来。
> 对照：`LibrarySys.cpp:145-147` 传的全是 `false`，所以现在没暴露；一旦某处要传 `true` 就骗人。

### 缺陷 2　`Book::display()` 里有个空 if
`Book.cpp:110-113`：`if (m_isBorrowed) { }` 函数体是空的，什么都不打印。

### 缺陷 3　`User::returnBook()` 只减计数，不删记录
`User.cpp:97-107`：`m_borrownum--` 之后 `m_records` 数组原封不动。
后果：借第 1 本 → 还掉 → 再借 → 新记录覆盖 `m_records[0]`，但名单里还留着旧书。而且**还错书也不会报错**（函数压根没检查还的是不是他借的那本）。
这一条正好是"组合关系里整体类没管好部分对象状态"的反例。

### 缺陷 4　`m_records[60]` 是魔法数字
`User.h:20` 开 60 格，人最多借 3 本（`m_maxnum`），且 `User::borrowBook` 里没有越界检查。实验五换 `vector` 时正好解决。

### 缺陷 5　"逾期罚款"完全没实现
作业总要求里明确写了「系统会根据借还的日期判断是否逾期，若逾期计算罚款」，当前代码零实现（`BorrowRecord` 里连日期字段都没有）。答辩必问，阶段 7 必须补。

### 缺陷 6　`Book` 缺"页数"字段
指导书题目 3 的数据成员原文：图书名称、ISBN、出版社、价格、**页数**、在馆状态。
`Book.h:8-14` 没有页数 —— 这正是第一课任务 A 要补的东西（练习里先在简化类上练）。

### 缺陷 7　缺学生/教师两个用户类型
指导书要求区分**学生**（学号）和**教师**（工号），且**最大借阅数量不同**。现在只有一个 `User` 类。阶段 3（继承）解决：`User` 做基类，`StudentUser` / `TeacherUser` 派生，最大借阅数在构造时定。
