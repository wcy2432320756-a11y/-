# 第二课　组合与依赖：为什么借书必须传引用

## 一、先搞清楚：本章的底层直觉


### 先看一个失败

下面这段代码，是几乎所有人在实验二都会先写出来的版本。它完整、能编译、能运行，而且结果不对。

**先把最容易绊人的一件事摆在前面**：本章的 `Book` 有两个版本，参数个数不一样，从第一节到最后一节交替出现。

| | 本章练习版 `Book` | 你项目里的 `Book` |
|---|---|---|
| 在哪 | `lesson02.cpp` 及全章讲义示例 | `Book.h` / `Book.cpp` |
| 成员 | 3 个 `string` + `double` + `bool` | 5 个 `string` + `double` + `bool` |
| 带参构造 | 4 个参数 `(title, author, isbn, price)` | 7 个参数（`Book.h:19-21`） |
| ISBN getter | `getIsbn()`，小写 s | `getISBN()`，全大写 |
| `sizeof` | 112 | 176 |
| 我该照哪个写 | 学概念时照左边，交作业时照右边 | |

两个都对，但**永远不能混着用** —— 混用会报 `C2661`（没有重载函数接受 N 个参数）或 `C2039`（`getIsbn` 不是 `Book` 的成员）。判断口诀：练习代码里的 `Book` 一律 4 个参数、`getIsbn`；项目里的 `Book` 一律 7 个参数、`getISBN`。

至于下面这个示例，它比表里那个练习版还更简：只有"标题 + 借出状态"两个字段，构造收 2 个参数 `Book("书名", false)`。纯粹是为了让第一个例子短到一眼看完 —— 从第三节起就换成表里那个 4 参的练习版了。

```cpp
#include <iostream>
#include <string>
#include <windows.h>
using namespace std;

class Book
{
private:
    string m_title;
    bool   m_isBorrowed;

public:
    Book(string title, bool isBorrowed)
        : m_title(title), m_isBorrowed(isBorrowed) { }

    string getTitle() const { return m_title; }
    bool   getIsBorrowed() const { return m_isBorrowed; }
    string statusText() const { return m_isBorrowed ? "已借出" : "可借"; }
    void   setIsBorrowed(bool b) { m_isBorrowed = b; }
};

void borrow(Book b)
{
    b.setIsBorrowed(true);
}

int main()
{
    SetConsoleOutputCP(65001);

    Book book("C++ Primer", false);

    cout << "借之前：" << book.statusText() << endl;
    borrow(book);
    cout << "借之后：" << book.statusText() << endl;

    return 0;
}
```

真实输出：

```
借之前：可借
借之后：可借
```

### 怪在哪

`borrow` 函数里明明写了一句 `b.setIsBorrowed(true);`，`main` 里也明明调用了 `borrow(book);`。

结果借了跟没借一样。

这不是"有时候能跑有时候不能"，也不是编译器抽风。**它每一次都这样。** 换编译器、换电脑、改个变量名，结果都一样。

现在把这个"怪"记牢。这一章剩下的所有内容，都是为了解释它、并且修掉它。

### 答案先给一句

**函数里的 `b`，和 `main` 里的 `book`，是两个不同的对象。**

它们长得一模一样（同样的书名、同样的状态），但住在内存里两个不同的位置。`borrow` 里那句 `setIsBorrowed(true)` 改的是 `b`，`book` 从头到尾没有被人碰过。

上面那个 `borrow` 的参数写法 `Book b`，叫**值传递**（pass by value）。第二节会把它拆到底，还会让你亲眼看到这两个对象的内存地址不是同一个。现在只需要先接受一句话：

> **"长得一样"不等于"是同一个"。**

### 所以本章到底在解决什么

把刚才那件事放大一点看，你会发现它不是孤例。

写借书这个功能，你其实要干三件事，而三件事全都会撞上同一类麻烦：

1. 读者身上得有个地方，记住"我借了哪几本书"。—— 这个"地方"怎么造出来？它什么时候被造？什么时候被销毁？
2. 借书这个动作，要改到书库里那本真书的状态。—— 改动怎么才能从函数里传出去？
3. 有些函数只是打印、只是查询，根本不该改数据。—— 怎么既让它别拷贝、又保证它不会手滑改掉东西？

第 1 条是**组合**，第 2 条是**依赖**，第 3 条是 `const` 引用。

三个问题，一个根。

> **本章所有内容，都在解决"状态怎么在两边同步"这一个问题。**

记住这句话。后面每一节你如果觉得"这跟借书有什么关系"，回到这一句，就知道自己在哪。

### 要同步的到底是哪两处状态

作业原文（实验二）是这么写的：

> 学生类抽象出借了什么书、借了几本；书类抽象出可借不可借的状态；借阅成功时两者状态都改变，参数必须是地址（指针或引用）；借阅要判断双方状态都允许才成功并输出结果。

这段话信息量很大，一处一处拆：

| 作业原话 | 翻译成代码 |
|---------|-----------|
| 学生类抽象出借了什么书、借了几本 | `User` 里要有记录容器，还要有一个"借了几本"的计数 |
| 书类抽象出可借不可借的状态 | `Book` 里那个 `bool m_isBorrowed` |
| **借阅成功时两者状态都改变** | 书那边 `m_isBorrowed` 变 `true`；人那边计数加一、记录里多一条 |
| **参数必须是地址（指针或引用）** | 借书函数的参数不能是 `Book b`，只能是 `Book& b` 或 `Book* b` |
| 借阅要判断双方状态都允许 | 人的额度没满 **并且** 书没被借出，两条都成立才借 |

关键在第三行和第四行。**"两者状态都改变"和"参数必须是地址"是同一件事的因果**：不改参数写法，状态就同步不了。你上面那个 `borrow(Book b)` 就是反例，它能编译能跑，就是不能同步。

### 两个概念的名字

上表里"记录容器"和"参数"这两处，分别对应本章的两个主角：

| 概念 | 一句话定义 | 在你项目里的具体位置 |
|------|-----------|---------------------|
| **组合**（composition） | 一个类的**成员变量**，类型是另一个类的对象 | `User.h` 第 20 行 `BorrowRecord m_records[60];`，以及 `User.h` 第 8 行 `Book m_book;` |
| **依赖**（dependency） | 一个类的**成员函数的参数**，是另一个类的对象（引用或指针） | `User.h` 第 34 行 `void borrowBook(Book& book);`、第 35 行 `void returnBook(Book& book);` |

> **"成员变量"是什么**：写在 `class { ... }` 花括号里面、`private:` 或 `public:` 下面的变量。第一课你已经写过 `string m_title;` —— 那就是成员变量。每个对象各有一份自己的。
> **"成员函数"是什么**：同样写在 `class { ... }` 里面，但是个函数。第一课写的 `display()` 就是。

> **"引用"和"指针"是什么**：两种"不复制对象、直接把对象本身交出去"的写法。引用写成 `Book& b`，指针写成 `Book* b`。后面的讲义会把它们彻底讲清。现在你只需要知道：`Book& book` 这个写法里的 `&`，就是让函数拿到"书库那本书本人"，而不是复制品。

### 用一个生活场景记住区别

- 你**拥有**你的手机。手机跟着你，你摔了它一起摔，你丢了它一起没。它的命运跟你的绑在一起。—— 这是组合。
- 你**依赖**图书馆门口的刷卡机。你刷一下就走，机器不是你的，坏了也不是你修，你没来的时候它照常待在那儿。—— 这是依赖。

这个区别不是文字游戏，它在代码里有很硬的后果：

| | 组合（成员对象） | 依赖（函数参数） |
|---|---|---|
| 什么时候诞生 | 宿主对象被创建时，**自动**跟着创建 | 函数被调用时，**从外面传进来** |
| 什么时候消失 | 宿主对象销毁时，**自动**跟着销毁 | 函数一返回，通道就断 |
| 你要不要写代码管它 | 不用，编译器全自动 | 要，你得决定参数怎么传 |
| 不注意会出什么错 | 不知道它什么时候被构造（后面专门有一节讲） | 改动丢了 —— 就是你刚才看到的那个 `借之后：可借` |

### 接下来要解决的四件事

```
1. 值传递为什么改不动          —— 就是你现在看到的这个现象，第二节拆到底
2. 引用 Book& 绑定的到底是什么  —— 以及指针 Book* 差在哪
3. 为什么到处都是 const Book&   —— 只读函数怎么既省拷贝又不会手滑
4. 拼成一次完整的借书调用链      —— 上面几样合起来才是一个能用的借书动作
```

每一件都落在你的 `Book` 和 `User` 上，不是空谈概念。

## 二、值传递：函数拿到的是复印件


### 先把三个词说清楚

| 词 | 是什么 | 例子 |
|---|---|---|
| **形参**（形式参数） | 函数**定义**里括号中的那个变量，它只在函数内部有效 | `void borrow(Book b)` 里的 `b` |
| **实参**（实际参数） | 函数**调用**时真正传进去的东西 | `borrow(book)` 里的 `book` |
| **值传递**（pass by value） | 一种传参方式：函数不接收实参本身，而是接收实参的**一份复制品** | 参数后面什么都不加，就是值传递 |

一句话：**形参是函数自己家的抽屉，值传递就是把实参的东西抄一份放进这个抽屉。** 抽屉里怎么翻，跟人家家里没关系。

### 实验：一次跑出三件事

这个程序你**必须自己敲一遍、跑一遍**。它一次就能把值传递的三个后果全部暴露出来。

```cpp
#include <iostream>
#include <string>
#include <windows.h>
using namespace std;

class Book
{
private:
    string m_title;
    bool   m_isBorrowed;

public:
    Book(string title, bool isBorrowed)
        : m_title(title), m_isBorrowed(isBorrowed)
    {
        cout << "  [构造]     《" << m_title << "》 出生" << endl;
    }

    // 拷贝构造函数：用一个已有的 Book 造一个新的 Book 时，自动被调用
    Book(const Book& other)
        : m_title(other.m_title), m_isBorrowed(other.m_isBorrowed)
    {
        cout << "  [拷贝构造] 《" << m_title << "》 被复制了一份" << endl;
    }

    ~Book()
    {
        cout << "  [析构]     《" << m_title << "》 销毁" << endl;
    }

    string getTitle() const { return m_title; }
    bool   getIsBorrowed() const { return m_isBorrowed; }
    string statusText() const { return m_isBorrowed ? "已借出" : "可借"; }
    void   setIsBorrowed(bool b) { m_isBorrowed = b; }
};

void borrow(Book b)
{
    cout << "  形参 b 的地址     = " << static_cast<const void*>(&b) << endl;
    b.setIsBorrowed(true);
    cout << "  函数里改完，b 是   " << b.statusText() << endl;
}

int main()
{
    SetConsoleOutputCP(65001);

    Book book("C++ Primer", false);

    cout << "实参 book 的地址   = " << static_cast<const void*>(&book) << endl;
    cout << "借之前             = " << book.statusText() << endl;
    cout << "sizeof(Book)       = " << sizeof(Book) << " 字节" << endl;
    cout << "---- 调用 borrow(book) ----" << endl;

    borrow(book);

    cout << "---- 回到 main ----" << endl;
    cout << "借之后             = " << book.statusText() << endl;

    return 0;
}
```

真实输出（地址每次运行都会变，你要看的是"两个数字是否相同"）：

```
  [构造]     《C++ Primer》 出生
实参 book 的地址   = 000000DD4A11F750
借之前             = 可借
sizeof(Book)       = 40 字节
---- 调用 borrow(book) ----
  [拷贝构造] 《C++ Primer》 被复制了一份
  形参 b 的地址     = 000000DD4A11F728
  函数里改完，b 是   已借出
  [析构]     《C++ Primer》 销毁
---- 回到 main ----
借之后             = 可借
  [析构]     《C++ Primer》 销毁
```

这段输出里藏了三件事，下面一件一件看。

### 第一个现象：两个地址不一样

```
实参 book 的地址   = 000000DD4A11F750
形参 b 的地址     = 000000DD4A11F728
```

**不一样。** 这就是全部答案。

> **"地址"是什么**：每个对象在内存里都有一个位置编号，就像门牌号。`&book` 的意思是"取 `book` 的地址"。`cout` 直接打印一个指针变量是打印不出好看的东西的，所以用 `static_cast<const void*>(&book)` 把它转成"纯地址"再打印。这个转换是给 `cout` 看的，不影响 `&book` 本身的意思。

如果两个地址一样，说明它们是同一个对象；不一样，说明是两个对象。现在不一样，所以 `b` 和 `book` 是**两个独立的对象**。

### 为什么不一样：调用函数时发生的三件事

执行 `borrow(book);` 这一行时，C++ 干了三件事：

**第一件：给 `borrow` 开一块新的内存区，叫栈帧。**

> **"栈"和"栈帧"是什么**：栈（stack）是程序运行时一块专门用来放"函数临时数据"的内存区，它的管理方式是"后进先出"——最后进去的最先出来。
> 每次调用一个函数，系统就在栈上给这个函数切一小块专用空间，里面放它的形参、局部变量、以及"这个函数返回后该回到哪一行"。这一小块就叫这个函数的**栈帧**（stack frame）。
> 函数一返回，它的栈帧就整个作废，里面的东西全部消失。**这就是为什么函数里定义的普通变量，函数一结束就没了。**

`b` 就住在 `borrow` 的栈帧里，地址是 `0x...F728`。`book` 住在 `main` 的栈帧里，地址是 `0x...F750`。两个不同的家。

**第二件：把实参的内容抄进形参。**

这一步不是简单的"复制字节"，而是调用了一个专门的函数 —— **拷贝构造函数**。

> **"拷贝构造函数"（copy constructor）是什么**：一种特殊的构造函数，专门用来"拿一个已有对象，造一个一模一样的新对象"。它的长相固定：参数是这个类自己的 `const` 引用。
> ```cpp
> Book(const Book& other);      // 这就是拷贝构造函数的标准长相
> ```
> 你不写，编译器会自动送你一个（它会把每个成员逐个拷过去）。你写了，编译器就用你的。
>
> 注意它的参数必须是**引用**（那个 `&`）。如果写成 `Book(Book other)`，那"用 `other` 造新对象"这件事本身又要拷贝一次，又要调拷贝构造，又要拷贝……无限递归。**这是 C++ 里引用非用不可的第一个硬理由**，后面的讲义会展开。

上面那个程序里，我们手写了一个拷贝构造函数，所以你能在输出里看到它被调用了：

```
  [拷贝构造] 《C++ Primer》 被复制了一份
```

**第三件：开始执行函数体。** 从这一行起，`b` 是一个完整、独立、内容一模一样的对象。

### 内存图：原件和复印件

```
main 的栈帧                              borrow 的栈帧
book 住在 0x...F750                      b 住在 0x...F728
+-------------------------------+        +-------------------------------+
| m_title        "C++ Primer"   |        | m_title        "C++ Primer"   |
| m_isBorrowed   false          |        | m_isBorrowed   true           |
+-------------------------------+        +-------------------------------+
        ^                                        ^
        原件                                     复印件
        从头到尾没人碰过                          函数里改的是这个
```

看清楚这幅图，你就理解了本章一半的内容。

- 左边是 `main` 里的 `book`，它一直躺在 `main` 的栈帧里，从程序开始到 `main` 结束。
- 右边是 `borrow` 里的 `b`，它是**临时造出来的**，函数一返回就销毁。
- `setIsBorrowed(true)` 执行时，只把右边的 `false` 改成了 `true`。左边的 `false` 一直没动。
- 函数返回后，右边整个格子消失。改动跟着消失。

> **字符串也另拷了一份**：`m_title` 是 `string`，拷贝时不是"两个对象共用一段文字"，而是**新分配一块内存、把字符抄过去**。这叫**深拷贝**（deep copy）。所以两份字符串互不影响。`bool` 是基本类型，直接拷一个数值。

### 后果一：状态改不动

这是最直接的后果，也是作业里最致命的那个。

```cpp
void borrow(Book b)     // 值传递
{
    b.setIsBorrowed(true);       // 改的是复印件
}

borrow(book);
// book 还是"可借"
```

真实输出那一行：

```
借之后             = 可借
```

借书成功了（函数跑完了，没报错），但书库里那本书的状态**一点没变**。

> **所以实验二为什么白纸黑字写"参数必须是地址（指针或引用）"？**
> 因为只要参数是 `Book b`，函数就永远改不到书库里那本真书。"借阅成功时两者状态都改变"这句话，用值传递在物理上做不到。这不是风格问题、不是好坏问题，是**做不到**。

### 后果二：一个大对象白白拷贝一次

看输出里这一行：

```
sizeof(Book)       = 40 字节
```

40 字节，好像不多？那是因为这个演示用的 `Book` **只有 1 个 `string` 和 1 个 `bool`**。

你项目里的 `Book`（`Book.h:8-14`）有 5 个 `string`（书名、作者、出版社、ISBN、编号）加 1 个 `double` 加 1 个 `bool`。用同样的方法实测：

```
sizeof(Book) = 176 字节
sizeof(string) = 32 字节
```

**176 字节。** 每一次 `borrow(book)` 调用，都要完整复制 176 字节，还要为其中 5 个字符串各自重新安排内存。

一次 176 字节听上去也没什么。但把它放进循环里：

```cpp
for (int i = 0; i < 10000; i++)
{
    borrow(book);        // 每次调用都拷贝 176 字节
}
```

一万次调用 = 拷贝 176 万字节。而且这只是"借一本书"这一个动作。你的系统里还有 `returnBook`、`display`、查询、排序……全用值传递的话，开销是成倍叠加的。

> **一个必须记住的量级感**：`int` 是 4 字节，一个指针是 8 字节，`string` 是 32 字节，一个像样的业务对象（`Book`）是 176 字节。
> **传 `int` 用值传递是对的**（拷 4 字节比"绕一层地址"还快）；**传 `Book` 用值传递是浪费**（拷 176 字节，还要额外分配堆内存）。

> **所以实验二为什么要求传地址？**
> 除了"改不动"这个硬伤，还有性能这一层。传地址只拷一个 8 字节的地址，不管对象多大，成本恒定。答辩时被问"传地址有什么好处"，答这两条：**能改到原对象**、**不产生拷贝开销**。

### 后果三：构造函数被调用两次

这一条最隐蔽，因为它在输出里不显眼，但它决定了很多"莫名其妙"的 bug。

数一下前面那段真实输出里跟构造有关的行：

```
  [构造]     《C++ Primer》 出生            ← 第 1 次：main 里创建 book
  [拷贝构造] 《C++ Primer》 被复制了一份     ← 第 2 次：调用 borrow 时造副本
```

**两次。** 你只写了一句 `Book book("C++ Primer", false);`，但构造函数被调用了两次 —— 一次是带参构造（造 `book`），一次是拷贝构造（造 `b`）。

再数析构：

```
  [析构]     《C++ Primer》 销毁            ← b 销毁
  [析构]     《C++ Primer》 销毁            ← book 销毁
```

也是两次。**有几次构造，就有几次析构。**

> **"析构函数"是什么**：名字是"波浪号 + 类名"（`~Book()`），没有参数、没有返回值，**对象销毁时自动调用**。第一课提过一句，这里第一次真正用上。它负责收尾：如果对象里 `new` 过内存，就在这里 `delete`。

这意味着什么？意味着**每一次值传递，都在悄悄创建一个新对象、又在函数结束时销毁它。**

如果这个类的构造函数或析构函数里干了有副作用的事 —— 比如打开文件、申请内存、打印日志、往全局列表里登记 —— 那每一次值传递都会**多干一遍这些事**。这类 bug 极难查：你只是调了个函数，结果某个全局计数器莫名其妙涨了。

> **所以实验二为什么强调"参数必须是地址"？**
> 第三条理由：值传递会**额外构造和析构一个对象**。对于 `Book` 这种简单数据类，后果是性能；对于将来那些"打开文件、持有资源"的类，后果就是功能错误。传地址不创建任何新对象，从根上避免了这件事。

### 三个后果，一张表

| 后果 | 现象 | 严重程度 |
|------|------|---------|
| 状态改不动 | 借了之后书还是"可借"，系统自相矛盾 | 功能错误，必须修 |
| 白拷贝一次 | 每次调用拷 176 字节，循环里成倍叠加 | 性能问题 |
| 构造/析构多跑一遍 | 构造函数调用两次，副作用执行两遍 | 隐蔽 bug |

三条加在一起，就是实验二那句话的全部理由：

> **"参数必须是地址（指针或引用）。"**

不是老师定的规矩，是**值传递在物理上解决不了"状态同步"这个问题**。

### 下一节要回答的问题

到这里你知道了：`Book b` 不行，得想办法把"书库那本书本人"交给函数。

C++ 给了两种写法：

```cpp
void borrow(Book& book);      // 引用：把本人交出去
void borrow(Book* book);      // 指针：把门牌号交出去
```

两种都算"传地址"，作业都认。但它们到底有什么区别、什么时候必须用哪个、`Book&` 里的 `&` 到底绑定了什么 —— 那是下一节的事。

在那之前，先记住第二节这一句话：

> **值传递 = 复印件。改复印件，原件不知道。**

## 三、引用传递：`Book& book` 到底绑定了什么


上一节看到的是失败的样子：值传递改不动原对象，两个地址不一样。这一节把地址对上，看引用是怎么做到"同一个对象"的。

### 3.1 只多了一个 `&`：两个版本并排

把两版函数贴在一起，你会看到全部差别就是**形参上多了一个字符**：

```cpp
// 值传递版
void passByValue(Book b)          // 形参是 Book 类型 —— 一个新的对象
{
    b.setIsBorrowed(true);
}

// 引用传递版
void passByRef(Book& b)           // 形参是 Book& 类型 —— 不是新对象，是别名
{
    b.setIsBorrowed(true);
}
```

函数体一个字都没变。`b.setIsBorrowed(true)` 这两行在源码里长得完全一样。

调用处的写法也完全一样：

```cpp
Book lib("C++ Primer", "Lippman", "9787121358579", 128.0);

passByValue(lib);      // 不加任何符号
passByRef(lib);        // 一样，也不加任何符号
```

三个地方摆在一起，**唯一不同的地方只有形参声明里的那个 `&`**：

| 位置 | 值传递版 | 引用传递版 | 差别 |
|------|---------|-----------|------|
| 形参声明 | `Book b` | `Book& b` | 多一个 `&` |
| 函数体 | `b.setIsBorrowed(true);` | `b.setIsBorrowed(true);` | 完全相同 |
| 调用处 | `passByValue(lib);` | `passByRef(lib);` | 完全相同 |

那为什么结果不同？因为那个 `&` 改的不是"怎么调用"，是**形参 `b` 这个身份本身**。

把两个版本各跑一次，同时在函数里打印形参的地址：

```cpp
void passByValue(Book b)
{
    cout << "    形参 &b             = " << &b << "      <- 和 lib 不一样" << endl;
    b.setIsBorrowed(true);
}

void passByRef(Book& b)
{
    cout << "    形参 &b             = " << &b << "      <- 和 lib 一模一样" << endl;
    b.setIsBorrowed(true);
}
```

真实输出（地址在你机器上会不一样，看关系就够）：

```
  lib 的地址            = 0000005398DFF640

  [值传递]
    形参 &b             = 0000005398DFF588      <- 和 lib 不一样
    调用后 lib 的状态    = 可借      <- 没改到

  [引用传递]
    形参 &b             = 0000005398DFF640      <- 和 lib 一模一样
    调用后 lib 的状态    = 已借出      <- 改到了
```

`&b` 打印出来的是 `b` 自己的地址。

- 值传递版打印 `...F588`，`lib` 在 `...F640` —— 两个不同的地址，说明 `b` 是另一块内存里的一本书。
- 引用传递版打印 `...F640`，和 `lib` 的地址一模一样 —— 说明 `b` 没有自己的内存，`&b` 问到的是 `lib` 的地址。

> **一句话记住**：值传递的形参有独立地址，引用传递的形参没有独立地址。这不是比喻，是 `&` 运算符当场能验证的事实。

### 3.2 `&` 这个符号在同一页里有三种身份

这是本章第一个必须单独点破的坑。初学者看到 `&` 就以为是"取地址"，看到 `Book&` 就懵了。实情是：**`&` 至少有三个不相干的身份，全靠上下文区分。**

```cpp
int x = 5;

int& a = x;        // 身份一：引用声明符 —— a 是 x 的另一个名字
int* p = &x;       // 身份二：取地址运算符 —— 取得 x 的内存地址
int c = x & 3;     // 身份三：按位与 —— 把 x 和 3 的二进制位逐个做与运算
```

三行代码，三个 `&`，三种完全不同的意思。而第一行和第三行的 `&` 在源码里长得几乎一样。

#### 判断口诀

**先看这一行是不是"声明一个变量"。**

| 这一行在干什么 | `&` 的意思是 | 例子 |
|---------------|-------------|------|
| 声明变量（有类型名 + 变量名） | **引用** | `Book& b = lib;`　`int& a = x;`　`void f(Book& b)` |
| 在一条声明里，跟在逗号后面 | 还是**引用**（声明延续） | `int &ra = x, &rb = x;` |
| 是表达式（在算一个值） | **取地址** | `p = &x;`　`f(&lib);`　`return &shelf[i];` |
| 两个整数值之间 | **按位与** | `x & 3` |

判据就一条：`&` 前面那个东西是**类型名**，还是**一个已经存在的值**。

- `Book &b = lib;` → `&` 前面是 `Book`，是个类型名，这一行在声明变量 → 引用。
- `p = &x;` → `&` 前面是 `=`，这一行在算一个值 → 取地址。

> **注意一个反直觉的地方**：`Book &b` 和 `Book& b` 和 `Book & b` **三种写法完全等价**，空格放在哪都合法，编译器只看 `&` 是不是在声明符里。所以"`&` 在类型后面就是引用、在变量前面就是取地址"这个说法是**错的** —— 因为 `Book &b` 里的 `&` 就紧挨在变量 `b` 前面，它仍然是引用。
>
> 别用空格位置做判断，用"这一行是不是声明"做判断。

#### 为什么这里特别容易混

因为同一个变量 `r`，你可以对它同时用两种身份，**两种写法都合法，但意思差着十万八千里**：

```cpp
Book lib("C++ Primer", "Lippman", "9787121358579", 128.0);

Book& r = lib;              // 引用：r 是 lib 的别名
Book* p = &r;               // 取地址：r 就是 lib，所以 &r 就是 lib 的地址

r.setIsBorrowed(true);      // 通过别名改一次
cout << &lib << "  " << &r << "  " << (&r == &lib) << "  " << lib.statusText() << endl;
```

第二行的 `&r` 拿到的地址，和 `&lib` **完全相等**。真实输出：

```
  &lib          = 0000005398DFF6D0
  &r            = 0000005398DFF6D0
  &r == &lib ?    true
  通过 r 改，lib 状态 = 已借出
```

`&r == &lib` 为 `true`，因为 `r` 根本不是另一个变量 —— 它就是 `lib`，只是多了个名字。

#### 第三条身份为什么也要提

因为 `a & b`（按位与）和 `Book& b`（引用声明）在肉眼上几乎没有区别，只差上下文。你在读别人代码时看到 `int & mask` 这种写法，只能靠"这一行在声明还是在算值"来判断。编译器不会含糊，人会。所以养成习惯：**看到 `&`，先问这一行在干什么。**

### 3.3 为什么说"引用不是新变量"

这不是口号，有三条可以当场验证的证据。

#### 证据一：`sizeof` 骗不了人

```cpp
cout << sizeof(Book)  << endl;     // 112   —— 我的简化版 Book（3 个 string），你项目那个会更大
cout << sizeof(Book&) << endl;     // 112   —— 完全一样
cout << sizeof(Book*) << endl;     // 8     —— 指针自己是个变量，占 8 字节
```

真实输出：

```
  sizeof(Book)   = 112
  sizeof(Book&)  = 112
  sizeof(Book*)  = 8
```

`sizeof(Book&)` 问的是"一个 `Book&` 占多大空间"，答案是 **112，等于被引用的那个对象本身**。因为它不是一块独立的内存，它就是那个对象。

指针的答案是 8 —— 指针**自己**是变量，存在栈上，占 8 字节（64 位下）。

把这个对比换成基本类型更直观：

```cpp
int  x = 5;
int& a = x;
int* px = &x;

cout << sizeof(a) << "   sizeof(px) = " << sizeof(px) << endl;
cout << "&a == &x ?   " << (&a == &x) << endl;
a = 99;
cout << "a = 99 之后 x = " << x << endl;
```

```
  sizeof(a) = 4   sizeof(px) = 8
  &a == &x ?   true
  a = 99 之后 x = 99
```

`a` 占 4 字节，`px` 占 8 字节。**如果 `a` 是个独立变量，它至少得有 8 字节装地址**。它没有，因为它不装地址 —— 它不存在。

#### 证据二：改 `a` 就是改 `x`，没有任何"传递"过程

```
  a = 99 之后 x = 99
```

`a` 和 `x` 之间没有"同步"这种动作，因为它们是同一块内存的两个名字。

#### 证据三：反汇编里，引用参数和指针参数一模一样

这一条最能说明问题。写两个函数，一个收引用、一个收指针，干的活完全相同：

```cpp
void byRef(Book& b) { b.setIsBorrowed(true); }
void byPtr(Book* b) { b->setIsBorrowed(true); }
```

用 `cl /FA` 生成汇编，两个函数的机器码**逐条相同**：

```
?byRef@@YAXAEAVBook@@@Z PROC
    mov     QWORD PTR [rsp+8], rcx
    sub     rsp, 40
    mov     dl, 1
    mov     rcx, QWORD PTR b$[rsp]
    call    ?setIsBorrowed@Book@@QEAAX_N@Z
    add     rsp, 40
    ret     0

?byPtr@@YAXPEAVBook@@@Z PROC
    mov     QWORD PTR [rsp+8], rcx
    sub     rsp, 40
    mov     dl, 1
    mov     rcx, QWORD PTR b$[rsp]
    call    ?setIsBorrowed@Book@@QEAAX_N@Z
    add     rsp, 40
    ret     0
```

（`rcx` 是 Windows x64 传第一个参数用的寄存器。`sub rsp, 40` 是在准备调用下一个函数所需的栈空间。）

两条指令序列一字不差。连编译器生成的异常展开记录也相同。唯一还能区分它们的是**函数名修饰**：`byRef` 修饰成 `?byRef@@YAXAEAVBook@@@Z`，里面 `AEA` 表示"引用"；`byPtr` 修饰成 `?byPtr@@YAXPEAVBook@@@Z`，里面 `PEA` 表示"指针"。差一个字母。

#### 三句话总结这里的分寸

| 层面 | 说的是什么 | 证据 |
|------|-----------|------|
| 语言标准 | 引用**不是对象**，它没有地址、没有大小，它只是一个已经存在的对象的别名 | `sizeof(Book&) == sizeof(Book)`；`&r == &lib` |
| 编译器实现 | 为了把"我指的是哪个对象"这个消息传进函数，编译器**必须**传一个地址过去。所以在寄存器/栈上，它用的就是指针的做法 | 上面那段逐条相同的汇编 |
| 你写代码时该怎么理解 | **按别名理解**。不要说"引用是个指针"，那样你会去猜它占几个字节、能不能改指向，全是错的 | `ref = b2` 不是改指向，是赋值（见 3.5） |

> **答辩时如果被问"引用和指针在底层是不是一回事"**：答"语义上不是 —— 引用不是对象，标准规定它没有地址和大小；实现上编译器通常用地址来实现它，所以反汇编看起来一样。这两句话不矛盾，一个说的是语言规则，一个说的是某台机器上的落地方式。"

### 3.5 引用的四条硬规则

这四条是从编译器那里学来的，不是约定 —— 违反任何一条都编不过，或者编过了但行为不是你想的那样。

#### 规则一：必须初始化，不能先声明后绑

```cpp
Book& r;              // 编译不过
```

MSVC 的报错原文（注意它的措辞顺序）：

```
error C2530: “r”: 必须初始化引用
```

引用一旦存在，就必须有指向。所以不能写 `Book& r; r = lib;` —— 第二行也不是"绑定"，那是给某个对象赋值（而且第一行已经编不过了）。

正确写法只有一种：声明的同时绑上。

```cpp
Book& r = lib;
```

如果业务上真的需要"先空着，晚点再决定指向谁"，那就该用指针：

```cpp
Book* p = nullptr;    // 先空着
p = &lib;             // 以后再指向
```

这条规则直接决定了第四节"什么时候必须用指针"。

#### 规则二：不能改绑，`ref = b2` 是赋值不是改指向

这是第二个大坑，比第一个更隐蔽 —— 因为它**编译通过、运行不崩、只是行为不是你想的那样**。

```cpp
Book b1("书A", "甲", "I-A", 1.0);
Book b2("书B", "乙", "I-B", 2.0);

Book& ref = b1;      // ref 绑到 b1
ref = b2;            // 你以为：ref 改绑到 b2
                     // 实际上：把 b2 的每个成员逐个抄进 b1

cout << "  ref = b2 之后：b1 标题 = " << b1.getTitle() << endl;
cout << "  &ref == &b1 ?    " << (&ref == &b1) << endl;
```

真实输出：

```
  ref = b2 之后：b1 标题 = 书B
  &ref == &b1 ?    true
```

两个结果一起看：

1. `b1` 的标题变成了 `书B` —— 说明 `b1` 被**改写了**。
2. `&ref == &b1` 仍然是 `true` —— 说明 `ref` **没有换绑**，它还绑在 `b1` 身上。

所以 `ref = b2` 的真实含义是"`b1 = b2`"。**引用从来不会换指向，这只是普通赋值。**

对比指针：

```cpp
Book b3("书C", "丙", "I-C", 3.0);
Book b4("书D", "丁", "I-D", 4.0);

Book* p = &b3;
p = &b4;             // 真·改指向

cout << "  p = &b4 之后：p 指向 = " << p->getTitle() << endl;
cout << "  b3 标题还是 = " << b3.getTitle() << endl;
```

```
  p = &b4 之后：p 指向 = 书D
  b3 标题还是 = 书C
```

`p` 现在指着 `b4`，而 `b3` 一个字节都没被碰。想换指，只能用指针。

> **第三课和第五课的伏笔**：正因为引用不能换指向，容器（`vector`）里不能放引用，只能用指针或对象副本。这一条现在先记住结论。

#### 规则三：引用不能为空

C++ 里没有"空引用"这种东西。一个引用在它整个生命周期里，永远绑在一个真实存在的对象上。

```cpp
Book* p = nullptr;                       // 合法
if (p != nullptr) { p->display(); }      // 所以这里要判空
cout << "  （上面什么都没打印，因为指针是空的，if 挡住了）" << endl;

Book& r = ???;                           // 没有"空引用"可以写
```

真实输出：

```
  （上面什么都没打印，因为指针是空的，if 挡住了）
```

注意这一行字不是程序打印的提示 —— **程序本身什么都没干**，是我在 `if` 后面自己加了一句 `cout` 你才看到字。如果你的代码里没有那句 `cout`，屏幕上就是一片空白。这就是判空的意义：**不判空不是"跳过"，是崩溃。**

这条是**优点还是缺点，取决于场景**：

- 写 `borrowBook(Book& book)` 时，它是优点 —— 编译器替你保证了"传进来的一定是一本真实存在的书"，你不需要写任何判空代码。
- 写"查书，查不到就返回"时，它是缺点 —— 你没法用引用表达"没有这本书"，只能用指针返回 `nullptr`，或者返回一个下标（`-1` 表示没有）。

这也是 4.4 节第一个"必须用指针"的场景。

#### 规则四：调用处不加 `&`

```cpp
passByRef(lib);       // 对的
passByRef(&lib);      // 编译不过
```

报错原文：

```
error C2664: “void passByRef(Book &)”: 无法将参数 1 从“Book *”转换为“Book &”
note: 参见“passByRef”的声明
note: 尝试匹配参数列表“(Book *)”时
```

`Book*` 和 `Book&` 是两个完全不相干的类型，编译器不给它们互转。

这是引用比指针舒服的地方：调用者看代码时，`f(lib)` 这个写法跟值传递**完全一样**，不需要记住"这个函数收地址还是收值"。

代价是：**看调用处看不出来它会不会被改**。这是引用在工程上唯一的缺点，只能靠函数签名（`Book&` 还是 `const Book&`）来读。

### 3.6 落回实验二：借书为什么 `Book&` 就够了

作业原文写的是"参数必须是地址（指针或引用）"—— 两者都合规。你选引用，要能说清理由。三条：

**第一条：调用处读起来像人话。**

```cpp
yg.borrowBook(b1);       // 引用：yg 借 b1
yg.borrowBook(&b1);      // 指针：yg 借 b1 的地址
```

第二种写法里那个 `&` 是纯噪音。你在 `main` 里会给五六本书反复调这个函数，每处都多一个 `&`，每处都是一个可能敲漏的地方。

**第二条：引用不可能为空，省掉一整类防御代码。**

用指针就得这么写：

```cpp
bool borrowBook(Book* book)
{
    if (book == nullptr)          // 必须写，否则 nullptr 传进来直接崩
    {
        return false;
    }
    if (book->getIsBorrowed())    // 已经被别人借走了，不能再借
    {
        return false;
    }
    book->setIsBorrowed(true);    // 走到这里才真的借出去
    return true;
}
```

用引用，这两行直接不存在。答辩时老师问"你的函数怎么处理空指针"，你答"参数是引用，引用不可能为空，所以这一类输入在类型层面就被排除了" —— 这是一个满分的回答，因为它说明你知道**编译器替你挡住了什么**。

**第三条：函数体里访问成员用 `.`，不用 `->`，少一个出错点。**

```cpp
void borrowBook(Book& book)
{
    book.setIsBorrowed(true);      // 就是点
}
```

指针版每一处都要写 `book->setIsBorrowed(true)`。零基础最常见的错就是 `->` 和 `.` 用混（4.2 节专门讲），用引用直接从根上消掉这个错。

**那么指针留给谁？** 留给"可能没有"和"要换指"的地方。比如你要写一个"在书库里找书"的函数，找不到是很正常的结果：

```cpp
Book* findBook(Book shelf[], int n, const string& title);   // 找不到返回 nullptr
```

这个函数**没法**用引用返回值 —— 因为引用必须给出一个真实存在的对象，而"找不到"时没有对象可给。

**怎么在签名里一眼看出这本书会不会被改？**

| 签名 | 能改实参吗 | 会拷贝吗 | 什么时候用 |
|------|-----------|---------|-----------|
| `void f(Book b)` | 不能 | 会，整个对象拷一份 | 函数里需要的是一份可以随便糟蹋的副本 |
| `void f(Book& b)` | **能** | 不会 | 要把结果写回这本书（`borrowBook` / `returnBook`） |
| `void f(const Book& b)` | 不能（编译器强制） | 不会 | 只读，但对象很大不想拷贝（`display` / `printBook`） |

这三行就是本章签名选择的全部规则。你项目里 `borrowBook(Book& book)`、`returnBook(Book& book)` 属于第二行，是对的 —— 它们都要执行 `book.setIsBorrowed(...)`。

第三行那个 `const` 具体写在哪、锁住的是谁，见 5.3 的六行表 —— 那张表把 `const Book&`、`const Book*`、`Book* const`、`const Book* const` 一次拆完。这里只要记住"只读就用第三行"。

> **答辩常问的连环问题**："为什么 `borrowBook` 不加 `const`？" —— 答"因为它要改这本书的状态"。如果你真把它写成 `void borrowBook(const Book& book)` 再在里面调 `book.setIsBorrowed(true);`，MSVC 会当场拦住：
>
> ```
> error C2662: “void Book::setIsBorrowed(bool)”: 不能将“this”指针从“const Book”转换为“Book &”
> note: 转换丢失限定符
> note: 参见“Book::setIsBorrowed”的声明
> ```
>
> 读法是：`const Book&` 传进来的 `this` 是 `const Book*`，而 `setIsBorrowed` 的 `this` 要的是 `Book*`，`const` 丢了，不许。（`const` 的完整讲法在第五节。）

## 四、指针传递：和引用的区别，什么时候非它不可


### 4.1 最小语法对照

三个版本并排，把差别一次看清：

```cpp
// 值传递
void byValue(Book b)
{
    b.setIsBorrowed(true);        // 用点
}

// 引用传递
void byRef(Book& b)
{
    b.setIsBorrowed(true);        // 也是用点
}

// 指针传递
void byPtr(Book* b)
{
    b->setIsBorrowed(true);       // 用箭头
}

Book lib("C++ Primer", "Lippman", "9787121358579", 128.0);

byValue(lib);                     // 直接传
byRef(lib);                       // 直接传
byPtr(&lib);                      // 必须加 & 取地址
```

一张最小的对照：

| | 值 `Book b` | 引用 `Book& b` | 指针 `Book* b` |
|---|---|---|---|
| 形参是什么 | 一个新对象（副本） | 原对象的别名 | 一个装地址的变量 |
| 调用处怎么写 | `f(lib)` | `f(lib)` | `f(&lib)` |
| 函数里访问成员 | `b.getTitle()` | `b.getTitle()` | `b->getTitle()` |
| 能改到原对象吗 | 不能 | 能 | 能 |
| 形参自己的地址 | 和实参不同 | 和实参相同 | 自己有一块内存，值是实参地址 |

指针版跑出来的真实输出，注意第一行和第二行是**同一个数字**：

```
  lib 的地址 = 000000687FD9F740
  形参 b(值)   = 000000687FD9F740      <- b 里存的值，就是 lib 的地址
  调用后 lib 的状态 = 已借出
```

`b` 这个变量自己有地址（在栈帧里），里面**装的内容**是 `lib` 的地址。所以指针是"两层"：一层是变量自己，一层是它指向的东西。

引用只有一层。这就是两者最本质的结构差别。

### 4.2 `->` 和 `.`：零基础在这里必错

先把规则摆死：

> **左边是一个对象（或对象的引用）→ 用 `.`
> 左边是一个指针 → 用 `->`**

就这一句。但零基础几乎一定会写错一次，因为两种写法在源码里看起来"差不多"。

#### `->` 到底是什么

`p->f()` 是 `(*p).f()` 的缩写。展开读一遍：

```cpp
p->setIsBorrowed(true);
// 等价于
(*p).setIsBorrowed(true);
```

意思是：**先顺着 `p` 里存的地址找到那个对象（`*p`），再调它的 `setIsBorrowed`。**

那为什么不直接让你写 `(*p).f()`？因为 `*` 的优先级比 `.` 低。你写

```cpp
*p.setIsBorrowed(true);
```

编译器会先算 `p.setIsBorrowed`（对指针调成员，直接错），再对结果解引用。为了让"顺着指针取对象再取成员"这个高频操作写起来方便，C 语言设计了 `->` 这个符号。

> **记忆法**：箭头 `->` 本身就长得像"从指针走过去"—— 一横是门牌号，箭头指向那栋房子。`.` 是个点，点在一个东西上面，那个东西就在你手边。

#### 写错了会报什么

**错误一：指针上用了 `.`**

```cpp
Book* p = &lib;
p.setIsBorrowed(true);        // 错
```

```
error C2228: “.setIsBorrowed”的左边必须有类/结构/联合
note: 类型为 'Book *'
note: 是否改用“->”?
```

注意第三行 —— **编译器直接把答案告诉你了**。看到 `是否改用 ->` 这四个字，不用再想，就是这个问题。

**错误二：对象上用了 `->`**

```cpp
Book lib;
lib->setIsBorrowed(true);     // 错
```

```
error C2819: “Book”类型没有重载成员“operator ->”
note: 参见“Book”的声明
note: 是否改用“.”?
error C2232: “->Book::setIsBorrowed”: 左操作数有“class”类型，使用“.”
```

这次报了两条 error，第二条更直白：`左操作数有“class”类型，使用“.”`。

> **看报错的规律**：只要 MSVC 的 note 里出现 `是否改用“->”?` 或者 `是否改用“.”?`，那就是 `->` 和 `.` 用反了，改符号就行，不用查别的地方。这是全套报错里最容易被解决的一类，前提是你认得它。

#### 一个连锁的坑：`*p.f()` 为什么也不行

```cpp
*p.setIsBorrowed(true);       // 想表达"对 p 指向的对象调成员"
```

这不是"少写了括号"，是真的语法错。`*` 和 `.` 的优先级决定了它被解析成 `*(p.setIsBorrowed(true))` —— 先对指针 `p` 用 `.`，第一步就报 `C2228`，和你直接写 `p.setIsBorrowed` 报的是一模一样的三行。

要么加括号 `(*p).setIsBorrowed(true);`，要么直接用 `p->setIsBorrowed(true);`。工程上一律用后者。

#### 为什么指针数组特别容易混

因为这两行都合法，但意思完全不同：

```cpp
Book  shelf[3];        // 对象数组：shelf[i] 是一本书（对象）
Book* ptrShelf[3];     // 指针数组：ptrShelf[i] 是一个地址

shelf[0].getTitle();       // 点 —— shelf[0] 是对象
ptrShelf[0]->getTitle();   // 箭头 —— ptrShelf[0] 是指针
```

判断方法：**看 `[]` 前面是什么。** `Book shelf[]` 取出来的东西是 `Book`，用点；`Book* ptrShelf[]` 取出来的东西是 `Book*`，用箭头。

两条声明长得只差一个 `*`，取出的东西却差一整层 —— 这是 `->` 和 `.` 最容易翻车的地方，因为数组下标 `[0]` 把注意力全吸走了，你会忘了看前面那个 `*`。

### 4.3 一张必须背下来的对照表

| 维度 | 引用 `Book&` | 指针 `Book*` |
|------|-------------|-------------|
| 能不能为空 | **不能**，永远绑一个真实对象 | **能**，可以是 `nullptr` |
| 必须初始化吗 | 必须，`Book& r;` 编不过（`C2530`） | 不必，可以先 `Book* p = nullptr;` |
| 能不能重新指向别的对象 | **不能**，`ref = b2` 是赋值（3.5 规则二） | **能**，`p = &b2;` |
| 形参怎么写 | `void f(Book& b)` | `void f(Book* b)` |
| 调用处怎么写 | `f(lib)` | `f(&lib)` |
| 访问成员 | `b.getTitle()`　用点 | `b->getTitle()`　用箭头 |
| 要不要解引用 | 不用，拿到就是对象本体 | 要，`*b` 才是对象，`b->` 是"取对象再取成员" |
| 加 `const` 的写法 | 只有一种：`const Book&` | 三种：`const Book*`（锁数据）、`Book* const`（锁指针）、`const Book* const`（两头都锁） |
| 能不能做算术 | **不能**，没有 `r + 1` 这种东西 | **能**，`p + 1` 是下一个元素 |
| 占多少空间 | 不占（`sizeof(Book&) == sizeof(Book)`） | 8 字节（64 位） |
| 用错时的典型事故 | 几乎没有意外 —— 编译器帮你看住了一切 | 空指针崩溃、悬空指针、忘记解引用、忘记 `delete` |
| 典型用途 | 函数参数（要改或只读大对象）、返回值、给变量起别名 | 可能没有的东西、要换指、动态内存、遍历数组、容器里存位置 |

这张表的用法：**遇到一个"要不要用指针"的选择，从上往下扫一遍，只要有一行落在右边，就必须用指针；全是左边，就用引用。**

> **`const` 那两行的记忆法**：`const` 在 `*` 左边锁数据，在 `*` 右边锁指针。引用没有"右边"（引用天然不能改指向），所以引用只有 `const Book&` 一种写法。完整的 `const` 位置讲法在第五节。

### 4.4 什么时候必须用指针（引用做不到的四件事）

四条，每条一个能跑的例子。

四条共用一个前提 —— 下面这段 `Book` 和这个书库数组，粘在 `main` 开头就能把四条全部跑通，输出和本节贴的一致：

```cpp
class Book
{
private:
    string m_title;
    string m_author;
    string m_ISBN;
    double m_price;
    bool   m_isBorrowed;

public:
    Book() : m_title("(空)"), m_author(""), m_ISBN(""), m_price(0.0), m_isBorrowed(false) {}
    Book(string title, string author, string isbn, double price)
        : m_title(title), m_author(author), m_ISBN(isbn), m_price(price), m_isBorrowed(false) {}

    string getTitle()      const { return m_title; }
    string getAuthor()     const { return m_author; }
    bool   getIsBorrowed() const { return m_isBorrowed; }
    void   setTitle(const string& t) { m_title = t; }
    void   setIsBorrowed(bool b) { m_isBorrowed = b; }
    string statusText()    const { return m_isBorrowed ? "已借出" : "可借"; }

    void display() const
    {
        cout << "    《" << m_title << "》 " << m_author
             << " / " << m_ISBN << " / " << m_price << " 元 / " << statusText() << endl;
    }
};

Book shelf[3] = {
    Book("C++ Primer",    "Lippman", "9787121358579", 128.0),
    Book("算法导论",      "Cormen",  "9787111407010", 128.0),
    Book("Effective C++", "Meyers",  "9787111492245", 65.0)
};
```

`sizeof(Book)` 是 112：三个 `string`（MSVC 下每个 32 字节）共 96、一个 `double` 8 字节、一个 `bool` 1 字节，补齐到 8 的倍数正好 112。这是**本章练习版 `Book`** 的尺寸。

你项目里那个 `Book` 多两个 `string`（`m_publisher`、`m_id`），同样方法算出来是 **176** —— 我实测过。两个数都对，看你在量哪一个：后面凡是拿练习版代码演示的地方都是 112；凡是要估你自己项目里一个对象多大，用 176。对不上就说明你的 `Book` 成员和上面这个不一样。

#### 第一件：这个参数"可能没有"

引用必须绑在一个真实对象上，所以它没法表达"没有"。而"找东西找不到"是程序里最常见的合法结果。

```cpp
// 在书库里找一本书，找到返回它的地址，找不到返回 nullptr
Book* findBook(Book shelf[], int n, const string& title)
{
    for (int i = 0; i < n; i++)
    {
        if (shelf[i].getTitle() == title)
        {
            return &shelf[i];         // 找到 —— 返回这一格的地址
        }
    }
    return nullptr;                   // 找不到 —— 只有指针能表达这个
}
```

调用方必须判一下：

```cpp
Book* p = findBook(shelf, 3, "算法导论");     // 书库里有
if (p != nullptr)
{
    p->display();
}
else
{
    cout << "书库里没有这本书" << endl;
}

Book* q = findBook(shelf, 3, "不存在的书");   // 书库里没有
if (q != nullptr)
{
    q->display();
}
else
{
    cout << "书库里没有这本书" << endl;
}
```

真实输出：

```
    《算法导论》 Cormen / 9787111407010 / 128 元 / 可借
    书库里没有这本书
```

第二次调用返回的 `nullptr` 被 `if` 挡住了 —— 那一行 `书库里没有这本书` 才是重点：**程序没有崩，它正常地表达了一个"没有"**。换引用写，`findBook` 找不到时无值可返。

> **你项目里的现状**：`LibrarySys.cpp` 的 `int findBook(vector<Book>& books, const string& title)` 返回的是**下标**，找不到返回 `-1`。这就是"用 int 假装一个可能不存在的位置"，能跑，但要靠 `-1` 这个约定俗成的魔法值，调用方还得自己记住 `if (idx >= 0)`。用指针写就是 `Book*`，`nullptr` 是类型系统自带的"没有"，比 `-1` 干净。两种写法都对，答辩时能说出这个取舍就是加分。

#### 第二件：需要反复指向不同的对象

遍历一个对象数组时，你需要一个"游标"在元素之间移动。引用做不到这件事 —— 而且比"做不到"更糟：**硬写会静默改坏数据**。

```cpp
Book* cursor = &shelf[0];
for (int i = 0; i < 3; i++)
{
    cursor->display();
    ++cursor;                 // 换到下一个元素 —— 指针算术
}
```

指针 `+ 1` 的含义是"往后跳 `sizeof(Book)` 个字节"，正好落在下一个元素上。这是编译器按类型自动算的，你不需要知道 `Book` 到底多大。

引用版会长什么样：

```cpp
Book& cursor = shelf[0];
cursor = shelf[1];     // 你以为在换指向
                       // 实际在把 shelf[1] 整个抄进 shelf[0]！
```

这就是 3.5 规则二那个坑。**不是"引用不能换指向"这么轻描淡写，是"写出来会悄悄改坏数据"。** 所以需要移动的场景，一律用指针，别用引用试。

真实输出（指针版）：

```
    《C++ Primer》 Lippman / 9787121358579 / 128 元 / 可借
    《算法导论》 Cormen / 9787111407010 / 128 元 / 可借
    《Effective C++》 Meyers / 9787111492245 / 65 元 / 可借
```

#### 第三件：要在函数里改"指针本身"

这个场景很常见，但看起来很不像。比如"把指针挪到某本书上"这个动作，本身要改的是**指针变量**，不是它指向的对象。

```cpp
// 想改的是调用方那个指针 q，不是 q 指向的书
void pointToValue(Book* p, Book& target)
{
    p = &target;              // 只改了形参 p（一份拷贝），外面的 q 纹丝不动
}

void pointToRef(Book*& p, Book& target)
{
    p = &target;              // 改的是外面那个 q 本人
}
```

`Book*&` 怎么读：**从右往左读**。`&` 是引用，`*` 是指针，`Book` 是类型 —— "`p` 是一个引用，绑在一个 `Book*`（指向 Book 的指针）上"。

也就是"指针的引用"。传进来的是指针变量本身，不是它的副本。

真实跑一遍：

```cpp
Book b3("书C", "丙", "I-C", 3.0);
Book b4("书D", "丁", "I-D", 4.0);
Book* q = &b3;

pointToValue(q, b4);
cout << "  值传递版本后 q 指向 = " << q->getTitle() << "   <- 没改到" << endl;

pointToRef(q, b4);
cout << "  引用传递版本后 q 指向 = " << q->getTitle() << "   <- 改到了" << endl;
```

真实输出：

```
  值传递版本后 q 指向 = 书C   <- 没改到
  引用传递版本后 q 指向 = 书D   <- 改到了
```

同样的事情也能用二级指针写：

```cpp
void pointToPtr(Book** pp, Book& target)
{
    *pp = &target;            // pp 是"指向指针的指针"，解一层才是指针本身
}
```

`Book**` 读作"指向 `Book*` 的指针"。能用 `Book*&` 就别用 `Book**` —— 后者多一层解引用，每处访问都要多一个 `*`，而且调用处得写 `pointToPtr(&q, b4);`。`Book*&` 调用处写 `pointToRef(q, b4);`，干净。

> **这条同时说明了一个反直觉的事实**：引用不只能绑对象，也能绑指针变量。`Book*&` 就是"绑在一个指针上的引用"。你项目里 `User::borrowBook(Book& book)` 的 `book` 是"绑在一个 Book 上的引用"，机理完全一样。

#### 第四件：和 C 风格数组、动态内存打交道

这两样东西的接口天生就是指针，没有选择余地。

**C 风格数组当参数时会"退化"成指针：**

```cpp
void printShelf(Book arr[], int n)          // 看起来收的是数组
{
    cout << "    函数里 sizeof(arr) = " << sizeof(arr) << "   <- 退化成了指针" << endl;
    for (int i = 0; i < n; i++)
    {
        arr[i].display();
    }
}
```

真实输出：

```
    main 里 sizeof(shelf) = 336
    函数里 sizeof(arr) = 8   <- 退化成了指针
    《C++ Primer》 Lippman / 9787121358579 / 128 元 / 可借
    《算法导论》 Cormen / 9787111407010 / 128 元 / 可借
    《Effective C++》 Meyers / 9787111492245 / 65 元 / 可借
```

`main` 里 `sizeof(shelf)` 是 336（3 个元素 × 112 字节）。传进函数后只剩 8 —— 因为 `Book arr[]` 这个写法在形参位置上**就等于** `Book* arr`，数组的"长度信息"丢了。

这解释了两件事：

1. 为什么 `printShelf` 必须多收一个 `int n` —— 函数里已经算不出元素个数了。
2. 为什么你在 `main` 里写 `sizeof(shelf) / sizeof(shelf[0])` 能算长度（336 / 112 = 3），而在函数里这么写算出来永远是错的（8 / 112 → 0，两个指针相除也只能得 1）。**数组长度必须在数组还在的作用域里算好再传进去。**

**动态内存只认指针：**

```cpp
Book* makeBook(const string& t, const string& a)
{
    return new Book(t, a, "ISBN-NEW", 50.0);   // new 返回的永远是地址
}

Book* p = makeBook("堆上的书", "某人");
p->display();
cout << "地址 = " << p << "   sizeof(*heapBook) = " << sizeof(*p) << endl;
delete p;                          // delete 只接受指针
p = nullptr;                       // 删完置空，防悬空
cout << "delete 之后 = " << p << endl;
```

```
    《堆上的书》 某人 / ISBN-NEW / 50 元 / 可借
    地址 = 0000027DCAA250C0   sizeof(*heapBook) = 112
    delete 之后 = 0000000000000000
```

`new` 的返回类型就是 `Book*`，`delete` 的形参就是指针。整个动态内存机制建立在指针上，绕不过去。

> **第五章会撞上的坑**：`new` 出来的内存不会自己释放，`delete` 之后的指针不会自己变空（上面那行 `p = nullptr` 是你手动写的，不写它就是野指针）。用引用就完全不会有这两个问题 —— 引用既不 `new` 也不 `delete`，它只是别人的另一个名字。

### 4.5 落回作业：`User` 里存书目，对象数组还是指针数组

这是本章最后一处需要你自己做判断的地方，也是答辩很可能追问的点。

你的 `User` 要记下"这个人借了哪几本书"。有两种存法，都合法，后果完全不同。

#### 写法 A：对象数组，存副本（项目现在用的）

```cpp
struct BorrowRecord
{
    Book m_book;              // 一整个 Book 对象住在这里
};

class User
{
private:
    BorrowRecord m_records[60];
    int m_borrownum = 0;
};
```

（本节后面为了打印 `sizeof` 时数字好读，统一把 60 缩成 3。你项目里是 60，比例关系一样。）

借书时：

```cpp
m_records[m_borrownum].m_book = book;    // 把 book 的每个成员抄进这一格
m_borrownum++;
```

#### 写法 B：指针数组，存地址

```cpp
class User
{
private:
    Book* m_books[3];        // 只存门牌号，每格 8 字节
    int   m_borrownum = 0;

public:
    User()
    {
        for (int i = 0; i < 3; i++)
        {
            m_books[i] = nullptr;      // 必须手动初始化！
        }
    }
};
```

借书时：

```cpp
m_books[m_borrownum] = &book;    // 只存地址，书还是书库那一本
m_borrownum++;
```

#### 两种写法跑起来差在哪

同一本书，借出去之后改个书名，两种记录里看到的完全不同。先把两边的读写接口对齐（都缩到 3 格、只留能对比的部分）：

```cpp
class UserA
{
private:
    BorrowRecord m_records[3];
    int          m_borrownum = 0;
public:
    void borrow(Book& book) { m_records[m_borrownum].m_book = book; m_borrownum++; }
    const Book& record(int i) const { return m_records[i].m_book; }
};

class UserB
{
private:
    Book* m_books[3];
    int   m_borrownum = 0;
public:
    UserB() { for (int i = 0; i < 3; i++) { m_books[i] = nullptr; } }
    void borrow(Book& book) { m_books[m_borrownum] = &book; m_borrownum++; }
    Book* record(int i) const { return m_books[i]; }
};
```

注意两个 `record` 的返回类型：A 给的是 `const Book&`，B 给的是 `Book*` —— 这不是随便定的，它决定了调用处写 `.` 还是 `->`（见本节末尾）。

```cpp
Book lib("C++ Primer", "Lippman", "9787121358579", 128.0);
UserA ua;
UserB ub;
lib.setIsBorrowed(true);
ua.borrow(lib);
ub.borrow(lib);

lib.setTitle("C++ Primer 第5版");
cout << "  写法A（对象数组）记录里看到 = 《" << ua.record(0).getTitle() << "》" << endl;
cout << "  写法B（指针数组）记录里看到 = 《" << ub.record(0)->getTitle() << "》" << endl;
```

真实输出：

```
[借完之后改书名]
  写法A（对象数组）记录里看到 = 《C++ Primer》
  写法B（指针数组）记录里看到 = 《C++ Primer 第5版》
```

再改书的状态（还书）：

```cpp
lib.setIsBorrowed(false);
cout << "  写法A（对象数组）= " << ua.record(0).statusText() << "   <- 副本，跟书库脱节" << endl;
cout << "  写法B（指针数组）= " << ub.record(0)->statusText() << "   <- 同一本，实时同步" << endl;
```

```
[还书之后，记录里看到的这本书状态]
  写法A（对象数组）= 已借出   <- 副本，停在借出那一刻
  写法B（指针数组）= 可借   <- 同一本，书库改了它就跟着改
```

A 的记录里这本书永远显示"已借出"，因为它是借出那一瞬间的复印件；书库那边早就还了，它不知道。B 的记录里跟着变回"可借"，因为它看的就是书库那一本。

还有一点容易忽略：**B 那行 `ub.record(0)->statusText()` 里，`record(0)` 返回的是 `Book*`，所以后面跟 `->`；A 那行 `ua.record(0).statusText()` 返回的是 `Book&`，所以跟 `.`**。两种写法在调用处就长得不一样，这是 4.2 那条规则在真实代码里的样子。

尺寸也差着数量级：

```
  sizeof(Book)         = 112
  sizeof(BorrowRecord) = 112
  sizeof(UserA)        = 344    3 格副本 + 计数
  sizeof(UserB)        = 32     3 个指针 + 计数
```

344 对 32 —— 十倍还多。你的项目里是 60 格：写法 A 的 `User` 光记录就占 `60 × sizeof(Book)`。按项目那个 `Book`（5 个 `string` + 1 个 `double` + 1 个 `bool`，`sizeof` 实测 176）算，`m_records` 这一项就是 10560 字节，加上姓名和学号两个 `string`、两个 `int`，`sizeof(User)` 实测 **10632 字节（10.4KB）**；写法 B 是 `60 × 8 = 480` 字节。

（这里用的是精简版 `Book`，3 个 `string`。你项目里那个多两个 `string`，每一格的绝对值都会更大，但两类写法的比例关系不变：**对象数组每格要装一整本书，指针数组每格恒定 8 字节**。）

#### 后果对照

| | 写法 A　对象数组 | 写法 B　指针数组 |
|---|---|---|
| 记录里存的是什么 | 一整本书的完整副本 | 一个地址 |
| 每格占多少 | `sizeof(Book)`，你的项目里是 176 字节 | 固定 8 字节 |
| 书库那本书改名/改价后，记录跟着变吗 | **不跟**（是快照） | **跟**（同一本书） |
| 书库那本书被销毁后 | 记录仍然完整，安全 | **指针悬空**，一访问就崩 |
| 要求 `Book` 有默认构造函数吗 | **要求**（数组要逐个默认构造） | 不要求 |
| 删除中间一条记录要搬多少字节 | `sizeof(Book)` | 8 字节（只搬指针） |
| 删除记录时要不要负责 `delete` | 不用，自动析构 | **要**，否则内存泄漏 |
| 未初始化时是什么 | `Book` 的默认构造结果（安全） | **垃圾地址**（见下） |

最后一行值得单独看一眼。内置指针数组不做任何初始化：

```cpp
Book* raw[3];       // 没有初始化
Book  objs[3];      // 类类型数组，会自动调用默认构造函数
```

```
[内置指针数组不初始化]
  raw[0] = 0000000000000000
  raw[1] = 0000000000000000
  raw[2] = 000001BDB40076B0
[类类型数组自动构造]
  objs[0].getTitle() = (空)
```

**你跑一遍会得到和我不同的数字，这本身就是重点。** 我这台机器上前两格恰好是 `0`、第三格是垃圾；换台机器、换个编译选项、换个函数，可能三格全是垃圾，也可能全是 `0`。这个"有时看起来没事、有时炸"的特性正是指针最难查的地方 —— 你测试时它恰好是空的，一交上去老师在另一个环境里跑就崩。

`raw[0]` 里那串东西看着像个地址，顺着它访问就是一次崩溃。而 `objs[0]` 是一本构造好的、状态确定的书，`getTitle()` 一定返回合法 `string`。

这就是 4.5 开头那句"必须手动初始化"的原因，也是指针最容易出事的地方：**类类型数组会自动把每个元素构造成合法状态，指针数组什么都不做。**

#### 那到底该用哪个

**你的作业用对象数组（写法 A）。四个理由：**

1. **`BorrowRecord` 的语义是"借条"，不是"书的实时视图"。** 借条记的是"他借了哪本书、什么时候借的"，是借出那一瞬间的快照。书库后来把书名改成第 5 版，借条上应该还是当时那个书名 —— 这是对的，不是 bug。
2. **指针数组在第五章会炸。** 你后面要把书库换成 `vector<Book>`。`vector` 满了会重新分配一块更大的内存、把元素搬过去、**原来所有元素的地址全部失效**。如果你的记录里存着指向旧位置的指针，`vector` 一扩容，你所有借阅记录立刻集体悬空。这是一个非常真实、非常难查的崩溃。
3. **不用管 `delete`。** 对象数组里的 `Book` 跟着 `User` 一起自动析构，你不需要写任何清理代码。指针数组里每存一个 `new` 出来的地址，就欠一次 `delete`，谁欠谁还说不清。
4. **`Book` 已经有默认构造函数。** `Book.h:18` 那行 `Book();` 让对象数组可以直接开，写法 A 没有任何额外成本。（反过来，如果 `Book` 没有默认构造，对象数组根本编不过，会报 `error C2512` —— 这也是指针数组唯一真正的优势场景。）

**指针数组什么时候是对的？**

当你要表达的不是"借条"，而是"**这个人在看哪本书**"这种临时的、实时的指向关系时。比如一个"当前浏览位置"：

```cpp
Book* m_currentLooking = nullptr;      // 正在翻的那本书，翻完就清空
```

或者第五章之后，书库换成 `vector<Book>`，你想在记录里存**下标**而不是指针：

```cpp
struct BorrowRecord
{
    int    m_bookIndex;      // 存书在 vector 里的位置
    string m_borrowDate;     // 存借出时间
};
```

存下标比存指针稳 —— `vector` 扩容后下标照样有效，指针全废。这是第五章一个重要的取舍，现在先知道有这么回事。

> **答辩模板**：老师问"你为什么用对象数组存记录，不用指针数组？"
> 答"因为借阅记录的语义是快照，不是引用。用对象数组，记录和书库解耦，书库怎么改都不影响已成事实的借阅；而且它自动构造、自动析构，没有 `delete` 责任。用指针数组省空间，但书库容器一旦重新分配，所有指针同时悬空，风险远大于收益。"

## 五、`const Book&`：一个符号解决两个问题


### 5.1 需求不是凭空来的：一个 `printBook` 的两难

你在作业里迟早要写一个"把书打印出来"的函数。照着第一课的写法，你会先写成这样：

```cpp
void printBook(Book b)          // 传值
{
    b.display();
}
```

能跑。但它有个你看不见的代价：**每调一次，整本书被完整拷贝一份**。本章练习用的精简版 `Book` 里是 3 个 `string`、1 个 `double`、1 个 `bool`（你项目那个是 5 个 `string`，更大），在你这台机器的 MSVC 上：

```text
sizeof(Book) = 112 字节
```

也就是说 `printBook(b1)` 这一行，光对象本体就搬了 112 字节 —— 还不算 4 个 `string` 各自在堆上申请的内存。打印一本书根本不需要副本，你要的是"看"。

那改成引用：

```cpp
void printBook(Book& b)         // 引用，不拷贝了
{
    b.display();
}
```

不拷贝了，可新的问题来了：**这个函数现在能改你的书，而且编译器一句话都不会说**。

```cpp
void printBook(Book& b)
{
    b.setIsBorrowed(true);      // 谁写的？为什么？没人拦
    b.display();
}
```

调用方传进来的是一本自己的书，打印完发现状态被改了。

于是需求变成一句话，两个要求同时成立：

> 我不要拷贝，我也不许你改。

C++ 用一个符号同时办这两件事 —— 在引用前面加 `const`：

```cpp
void printBook(const Book& b)   // 不拷贝 + 不许改
{
    b.display();
}
```

`const Book&` 拆开读：`Book&` 是"就是外面那一本，不是副本"（解决拷贝），`const` 是"只能读，不能写"（解决误改）。一个形状，两个约束。

看程序里跑的地址对比（`lesson02.cpp` 5.1 段的真实输出）：

```text
外面那本书: 地址 000000286A5DE320
传值      : 形参地址 000000286A5DDF78  ← 和外面不是同一个对象
引用      : 形参地址 000000286A5DE320  ← 就是外面那一个
const引用 : 形参地址 000000286A5DE320  ← 也是外面那一个
```

第二行那个不一样地址就是拷贝出来的副本 —— 函数返回，它就被销毁了，你白拷了一次。第三、四行地址和外面完全相同：没有第二本书存在，只有同一个对象的不同叫法。

### 5.2 少写一个 `const` 是什么后果

同一个函数，只差一个 `const`：

```cpp
void printButCanChange(Book& b)     // 少写 const
{
    b.setIsBorrowed(true);          // 编译器：完全合法
    cout << "打印: 《" << b.getTitle() << "》" << endl;
}
void printSafely(const Book& b)     // 写了 const
{
    b.setIsBorrowed(true);          // 编译不过，下面 5.4 详说
}
```

真实运行结果：

```text
调用前状态: 可借
打印: 《算法导论》
调用后状态: 已借出   ← 编译器全程没吭声
```

注意最后那行注释。这里没有任何警告 —— 不是编译器漏了，是**你把权限给出去了**。`Book&` 的语义就是"给你改"，编译器没理由拦。`const` 的作用不是让程序更安全这种空话，它的作用是**在编译期把这类手滑挡下来**：只要你写了 `const`，那行 `setIsBorrowed` 就过不了编译，你当天就会发现，而不是等到答辩演示时数据莫名其妙变了。

### 5.3 `const` 的六种位置：一张表拆开讲

`const` 出现在哪个位置，锁的东西就不一样。这是本章最容易糊的地方，一次列清。

| 写法 | 谁被锁住 | 一句话人话 |
|------|----------|-----------|
| `const Book&` | 被引用的那个对象 | 我看这本书，但我保证不涂改它 |
| `Book const&` | 同上，**完全同一个类型** | 和上一行一模一样，只是把 `const` 挪到类型名右边 |
| `const Book*` | 指针指向的对象 | 我拿着这本书的地址，书不许改，但地址我可以换成别的书 |
| `Book* const` | 指针自己 | 地址焊死了，只能指这本，但这本书的内容我可以改 |
| `const Book* const` | 对象 + 指针 | 地址不许换，书也不许改，两头都锁 |
| `void f() const`（成员函数尾缀） | 这个函数里的 `this` | 这个函数承诺不改自己任何成员 |

判断方法只有一条，别背表：

> `const` 修饰的是**它左边紧挨着的那个东西**；左边没东西，才修饰右边。

- `const Book*`：`const` 左边没东西（在行首），所以修饰右边 `Book` → 书不许改。
- `Book const*`：`const` 左边是 `Book` → 修饰 `Book` → 和上一行**一样**。
- `Book* const`：`const` 左边是 `*` → 修饰指针自己 → 地址不许改。

六种写法在程序里都跑了一遍，真实输出：

```text
① const Book&        —— 不许改对象
    读到: 位置演示书
② Book const&        —— 和 ① 是同一个类型
    读到: 位置演示书（写法不同，类型完全相同）
③ const Book*        —— 不许改对象，可以换指向
    读到: 位置演示书
    指针已改成空: 是
④ Book* const        —— 可以改对象，不许换指向
    读到: 位置演示书
    价格已改成: 55
⑤ const Book* const  —— 两头都锁死
    读到: 位置演示书（数据和指向都不许动）
⑥ 成员函数尾缀 const —— this 变成 const Book*
    我是《位置演示书》，状态 可借（这个函数承诺不改任何成员）
```

三条要你自己验证过才算真懂：

**第一，`const Book&` 和 `Book const&` 是同一个类型，不是两个。** 别信"只是写法不同"这种口头说法，用编译器验：

```cpp
class Printer
{
public:
    void f(const Book& b);
    void f(Book const& b);      // 我以为这是重载
};
```

```text
error C2535: "void Printer::f(const Book &)": 已经定义或声明成员函数
note: 参见"Printer::f"的声明
```

编译器说"你已经声明过它了" —— 它俩在编译器眼里就是同一个函数，不是重载。名字不同（一个是 `const Book&` 一个是 `Book const&`），类型只有一个。

**第二，`const Book*` 想改书里的内容会报什么。** 试 `p->m_title = "改一下";`：

```text
error C2678: 二进制"=": 没有找到接受"const std::string"类型的左操作数的运算符(或没有可接受的转换)
note: 转换丢失限定符
```

后面还跟十几条 `note`，全是 `string` 的 `operator=` 候选，一条条说"不能把 `this` 从 `const std::string` 转成 `std::string&`"。**这些 note 不用看**，第一行就够了：`p->m_title` 因为 `p` 是 `const Book*`，取出来的 `m_title` 是个 `const std::string`，常量不能当赋值左边。

**第三，`Book* const` 想换指向会报什么。** 试 `p = &b;`：

```text
error C3892: "p": 赋值给类型为 'Book *const ' 的常量限定 变量
```

报错里那个 `Book *const ` 就是编译器把你写的东西还原成了完整类型 —— 它认的是"指针是常量"，不是"书是常量"。这行报错反过来能教你读类型。

### 5.4 零基础必踩的坑：getter 不加 `const` 尾缀

这是第五节唯一一个你**一定**会撞上的坑，撞上时你还看不懂报错。

假设 `Book` 的 getter 是这么写的（第一课就是这么写的，很自然）：

```cpp
class Book
{
public:
    const string& getTitle() { return m_title; }     // 没有 const 尾缀
};

void printBook(const Book& b)
{
    cout << b.getTitle() << endl;
}
```

编译，报错原文（MSVC 18，逐字未改）：

```text
error C2662: "const std::string &Book::getTitle(void)": 不能将"this"指针从"const Book"转换为"Book &"
note: 转换丢失限定符
note: 参见"Book::getTitle"的声明
note: 尝试匹配参数列表"()"时
```

四条信息，逐条翻译成人话：

1. **第一行**：我（编译器）在调 `Book::getTitle`，但这个函数要求 `this` 是 `Book*`（能改的），而你现在给我的是 `const Book`（不许改的）。两个类型对不上。
2. **`note: 转换丢失限定符`** —— 这句是全篇最关键的一句。"限定符"就是 `const`。"丢失"的意思是：把 `const Book` 当 `Book` 用，等于把 `const` 扔掉；编译器不许你偷偷扔，所以拒绝。
3. **`note: 参见"Book::getTitle"的声明`** —— 报错不在调用处，在声明处。往前翻到 `Book` 的类定义去看那个函数。
4. **`note: 尝试匹配参数列表"()"时`** —— `getTitle()` 一个参数都没传，所以不是"你传错参数了"，问题在函数本身。

**这个错不是"权限不足"，也不是"private 访问不了"**，很多人第一反应往访问控制上想，方向就错了。`getTitle` 是 public 的，能调；问题是它在 `const` 对象上**没资格被调**。

原因就一句话：**成员函数默认隐含一个非 const 的 `this`**。`const Book& b` 传进来的是 `const Book`，你调 `b.getTitle()` 时，编译器要拿 `&b`（类型 `const Book*`）去填 `getTitle` 的 `this`（类型 `Book*`），`const Book*` → `Book*` 是"丢 const"的转换，C++ 禁止。

**改法只有一种是对的：给 getter 加尾缀 `const`。**

```cpp
class Book
{
public:
    const string& getTitle() const { return m_title; }     // ← 尾缀 const
    //                      ↑
    // 加了它，this 的类型从 Book* 变成 const Book*，
    // 于是 const Book 也能传进来，上面的转换就不再"丢 const"了
};
```

尾缀 `const` 的含义不是"这个函数返回 const"，是"**这个函数承诺不改成员**"，编译器真的会检查：

```cpp
int getPrice() const
{
    m_price = 100.0;        // 编译不过：const 函数里改成员
    return m_price;
}
```

一旦承诺，反悔就编译不过。所以这不是装饰，是双向的契约：你调我，我保证不动你的数据；我保证不了，编译器替你保证。

顺带说清一个常见的误会：**加 `const` 不会影响原来的调用**。非 const 对象照样能调 const 成员函数（`Book b; b.getTitle();` 完全合法），因为"不修改"这个承诺对能改的对象也成立。所以给 getter 加 `const` 是纯收益，不会破坏第一课已经写好的代码。

### 5.5 落回你的作业：`Book.h` 里哪几个函数要加

打开你的 `Book.h`，看这两个区段（行号是现在文件里的实际行号）：

```cpp
// Book.h:22-29  获取
string getTitle();           // ← 要加
string getAuthor();          // ← 要加
string getPublisher();       // ← 要加
string getISBN();            // ← 要加

void setPublisher(string publisher);      // ← 不能加

判断标准不是"看起来像"，是**函数体里到底改没改成员**：

- `getXxx()` 全部是 `return m_xxx;`，一个字都不写成员 → 加 `const`。
- `setXxx(...)` 里全是 `m_xxx = 参数;` → **加不了**。加了立刻编译不过（这正是 `const` 该干的事）。
- `display()` 里全是 `cout <<`，不写成员 → 加 `const`。

改完之后，你才会遇到真正的问题，也是第六节要解决的：`User` 里怎么存这些 `Book`。

`display() const` 一旦加上，它内部就能调其他 `const` 成员函数，但**不能**调非 const 的。所以顺序要对：先给所有 getter 加 `const`，最后给 `display()` 加 —— 反了的话 `display() const` 里调 `getTitle()` 又会报 C2662。

**顺带定一件事：借还判断"是不是同一本书"，用 `m_ISBN` 还是 `m_id`？**

两个字段都在 `Book` 里，含义不同：

| 字段 | 含义 | 能不能重复 |
|------|------|-----------|
| `m_ISBN` | 国际标准书号，一本书的"型号" | 同一种书买了两本，ISBN 相同 |
| `m_id` | 馆内自己编的编号（贴书脊上那个条码） | 每一本实体书唯一 |

所以：**判断"这本书是不是我手上那本"要用 `m_id`** —— 图书馆里可能有两本一模一样的《C++ Primer》，ISBN 一样，但条码不同，他借的是甲本，甲本被弄丢了，乙本还在架上，这两本不能混。判断"他是不是借过这一**种**书"才用 `m_ISBN`。

你现在这个阶段，`main` 里每本书只有一个实例，两个字段都不会重复，用哪个都能跑。但**写的时候就要想清楚**：`returnBook` 里那道校验如果按 `m_ISBN` 比，将来两本同 ISBN 的书就会互串。建议从一开始就用 `m_id` 判同一个实体，`m_ISBN` 只在"这本书馆里还有几本"这种统计上用。第十节任务 C 的参考实现就是按 `getId()` 判的，和你项目 `BorrowRecord::setBook` 那条路一致 —— 照它写。

## 六、组合：一个类的成员是另一个类的对象


### 6.1 先看它长什么样

组合（composition）就一句话：**一个类的成员变量，类型是另一个类**。

这个你在作业里**已经写了**，而且不知不觉写了两层。打开 `User.h`：

```cpp
// User.h:6-11
struct BorrowRecord
{
    Book m_book;                                  // 第 1 层：一条记录里组合一本书
    void setBook(Book& book) { m_book = book; }
    Book getBook() { return m_book; }
};

// User.h:13-20
class User
{
private:
    string m_name;
    string m_id;
    int m_borrownum;
    int m_maxnum;
    BorrowRecord m_records[60];                   // 第 2 层：User 里组合 60 条记录
};
```

两层都是组合，一层套一层。`User` 对象里真的住着 60 个 `BorrowRecord`，每个 `BorrowRecord` 里真的住着一本完整的 `Book`。画出来是这样：

```text
User 对象（一整块连续内存）
┌──────────────────────────────────────────┐
│ m_name / m_id / m_borrownum / m_maxnum   │
├──────────────────────────────────────────┤
│ m_records[0]                             │
│    └─ m_book: 书名/作者/出版社/ISBN/id/价/状态 │
├──────────────────────────────────────────┤
│ m_records[1]                             │
│    └─ m_book: ……                          │
├──────────────────────────────────────────┤
│ ……（共 60 个格子）                        │
├──────────────────────────────────────────┤
│ m_records[59]                            │
│    └─ m_book: ……                          │
└──────────────────────────────────────────┘
```

一个 `User` 对象占多少字节？`60 × sizeof(BorrowRecord)`，而 `sizeof(BorrowRecord)` 就等于 `sizeof(Book)` —— `BorrowRecord` 里只有一个 `Book` 成员，没别的东西。你项目里那个 `Book` 是 5 个 `string` + 1 个 `double` + 1 个 `bool`（`Book.h:8-14`），`sizeof` 实测 **176**；光 `m_records` 这一项就是 `60 × 176 = 10560` 字节，再加 `m_name`、`m_id` 两个 `string` 和 `m_borrownum`、`m_maxnum` 两个 `int`，`sizeof(User)` 实测 **10632 字节，即 10.4KB**。这个数字先记住，6.4 和 6.5 都会用到。

对比另一种写法（依赖）——把 `Book` 换成指针，书就不住在 `User` 里了：

```cpp
struct BorrowRecord
{
    Book* m_book;                                 // 只存一个地址，书在别处
};
```

一个是"书在抽屉里"，一个是"抽屉里放着一张纸条，写着书在哪"。这两种在内存布局、构造析构顺序、"改一边另一边变不变"上，全是两种不同的东西。

### 6.2 构造顺序：本章考点，必须讲透

这是本章唯一一个必考的知识点，也是作业里 `m_borrownum` 一上来就是垃圾值的根源。

规则三条，按执行顺序：

1. **成员对象先构造**，顺序是**成员在类里的声明顺序**（不是你在初始化列表里写的顺序）。
2. 全部成员构造完，**才执行本类的构造函数体**（那对花括号里的语句）。
3. 析构顺序**完全相反**：先执行本类析构函数体，再按声明的**逆序**析构成员。

`lesson02.cpp` 里用两个会打印的类把这件事摊开：

```cpp
class Part
{
private:
    string m_tag;
public:
    Part(const string& tag) : m_tag(tag)
    {
        cout << "  [构造] Part " << m_tag << endl;
    }
    ~Part()
    {
        cout << "  [析构] Part " << m_tag << endl;
    }
};

class Owner
{
private:
    Part m_a;
    Part m_b;
public:
    Owner() : m_a("m_a"), m_b("m_b")
    {
        cout << "  [构造] Owner 的构造体开始执行（m_a / m_b 早已造好）" << endl;
    }
    ~Owner()
    {
        cout << "  [析构] Owner 的析构体开始执行（m_a / m_b 还活着）" << endl;
    }
};
```

`main` 里只有一句 `{ Owner o; }`，外面套一对花括号。真实输出：

```text
下面一对花括号是一个作用域，出右括号 o 就析构：
  [构造] Part m_a
  [构造] Part m_b
  [构造] Owner 的构造体开始执行（m_a / m_b 早已造好）
  [析构] Owner 的析构体开始执行（m_a / m_b 还活着）
  [析构] Part m_b
  [析构] Part m_a
出了作用域，o 已经不在了。
```

盯住这六行的位置，它把所有顺序都写死了：

- 前两行是 `Part`。这说明**你写 `Owner()` 的花括号时，`m_a` 和 `m_b` 早就构造完了**。等你的花括号开始执行，两个成员已经是活的、有数据的状态。
- 第三行才是 `Owner` 自己的构造体。这是你唯一能写代码的地方。
- 第四行是 `Owner` 的析构体 —— 此时 `m_a` / `m_b` 还活着，你还能用它们。
- 第五、六行是 `m_b` 先死，`m_a` 后死。**逆序**。

为什么必须逆序？因为 `m_b` 的构造过程可能用到了 `m_a`（比如 `m_b` 的构造函数里读了 `m_a` 的值）。先构造的后析构，才能保证"我死的时候，我依赖的人还活着"。

**考点第一问：把初始化列表写反，输出会变吗？**

```cpp
Owner() : m_b("m_b"), m_a("m_a")      // 故意写成 b 在前
```

答案：**不变**，还是 `m_a` 先、`m_b` 后。因为构造顺序只由 `class Owner` 里 `m_a; m_b;` 的**声明顺序**决定，和你初始化列表里怎么排字无关。初始化列表的书写顺序只影响"每个成员用哪个参数初始化"，不影响"谁先被造"。

编译器会提醒你吗？分编译器。

GCC / Clang 有 `-Wreorder`，`-Wall` 里就带着，写反了会报一条 `'Owner::m_b' will be initialized after 'Owner::m_a'`。

MSVC 对应的警告是 C5038，但它**只在 `/Wall` 出** —— `/W3`、`/W4` 都不报。本机 VS 18 实测三次：

```text
cl /W3    → 0 条 C5038
cl /W4    → 0 条 C5038
cl /Wall  → warning C5038: 数据成员"Owner::m_b"将在 数据成员"Owner::m_a"后初始化
```

而本课 `build.ps1` 用的正是 `/W3`。**所以你列表写反了，编译器一声不吭，程序照跑，结果和你想的不一样。**

顺手记一个动作：以后怀疑这类"不报错但行为诡异"的问题，把 `build.ps1` 里的 `/W3` 临时改成 `/Wall` 再编一次，看有没有 C5038 这种平时被压住的警告。看完记得换回来 —— `/Wall` 会把标准库头文件里的东西也一起倒出来，噪音很大。

**那这条规则真正会炸在哪？**

上面那个例子只是"写反了但每组各用各的常量"，结果一样，看不出危害。真正会炸的是**后面的成员要拿前面成员的构造结果来用**：

```cpp
class Part
{
public:
    string m_tag;
    Part(const char* t) : m_tag(t) {}
    const string& tag() const { return m_tag; }
};

class Danger
{
    Part m_a;
    Part m_b;
public:
    Danger() : m_b("b"), m_a(m_b.tag().c_str()) {}   // 想用 m_b 去造 m_a
};
```

意图很清楚：先造 `m_b`，再拿它的内容造 `m_a`。但按声明顺序，`m_a` 先造 —— 此刻 `m_b` 还是一片没构造的内存，`m_b.tag()` 读的是野值。我本机实测：**编译零警告，运行到构造 `m_a` 那一刻直接崩**，退出码 `0xC0000409`，连第一行输出都没打出来，连跑 4 次 4 次崩。

想要"先造谁"，唯一的办法是改 `class` 里的声明顺序，把 `m_b` 挪到 `m_a` 前面。初始化列表管不了这件事。

**考点第二问：为什么 `m_borrownum` 会是垃圾值？**

按上面规则，`User` 构造时，`m_records`（60 个 `BorrowRecord`）会先被构造。`BorrowRecord` 自己没写构造函数，所以编译器给它一个隐式默认构造，它再用 `Book()` 把里面的 `m_book` 造出来 —— 两层，全是默认构造，60 次。

这也解释了一件事：**`Book.h:18` 那个 `Book();` 声明是必须存在的。** 删掉它，`BorrowRecord` 编不过，`User` 也编不过，报的就是下面 6.3 第三条的 C2512。

而 `m_borrownum` 是 `int`，`int` 的"构造"是什么都不做。**所以它的值是你这块内存上一位住户留下来的**，可能是 0，可能是 2004318071。第一课那张"初始化"表里已经说过，这里只是它在真实作业里的样子：如果你在 `User::User()` 里不写 `m_borrownum = 0;`，`getBorrownum()` 第一次返回的就是垃圾。

### 6.3 初始化列表：不只是"写法好看"

平时你可以偷懒：

```cpp
Book::Book(string t)
{
    m_title = t;         // 构造体里赋值，能跑
}
```

但有三类成员，这么写**根本编不过**。这三类必须用初始化列表，没有第二条路。

**第一类：`const` 成员。**

```cpp
class BookWithConstIsbn
{
private:
    const string m_isbn;
public:
    BookWithConstIsbn(const string& isbn)
    {
        m_isbn = isbn;               // 想在这里赋值
    }
};
```

```text
error C2678: 二进制"=": 没有找到接受"const std::string"类型的左操作数的运算符(或没有可接受的转换)
note: 转换丢失限定符
```

还是那个"转换丢失限定符"。因为 `const` 成员一旦构造完就是常量，而函数体里的 `=` 是**赋值**，赋值给常量不合法。初始化列表不是赋值，是**构造** —— 它在对象诞生的那一刻就把值放进去。

```cpp
    BookWithConstIsbn(const string& isbn) : m_isbn(isbn) {}     // 对
```

有一个细节值得单独记：**如果你不写初始化列表，const 成员会走它自己的默认构造**。下面的代码是**能编译通过**的：

```cpp
class Book
{
private:
    const string m_isbn;
public:
    Book() {}        // 没初始化 m_isbn，也编过了
};
```

因为 `string` 有默认构造函数，`m_isbn` 被默认构造成空串 —— 这也是一种"初始化"。真正编不过的是 `int` 这种没有构造函数的类型：

```cpp
    const int m_id;
public:
    Book() {}        // 这个就编不过：const int 必须被初始化
```

**第二类：引用成员。**

```cpp
class User
{
private:
    string& m_school;
public:
    User(string& s)
    {
        m_school = s;                // 想在这里绑
    }
};
```

```text
error C2530: "User::m_school": 必须初始化引用
```

引用必须在诞生的那一刻就绑上，而且一辈子不能换。函数体开始执行时引用已经"出生"了 —— 它必须绑在什么东西上，你没给，编译器没法造。

```cpp
    User(string& s) : m_school(s) {}        // 对
```

再补一句容易误会的：`m_school = s;` 写在函数体里，即便能编译，那也**不是"绑定"，是"把 s 的内容赋给 m_school 指向的那个 string"**。引用不能重新绑定，这是它和指针最大的区别。

**第三类：成员对象没有默认构造函数。**

假设你的 `Book.h` 只留了带参构造，把 `Book.h:18` 那行 `Book();` 删了：

```text

因为造 `Student` 时必须先造 `m_borrowed`，而你项目里那个 `Book` 的构造函数要求七个参数（`Book.h:19-21`）。`Student()` 一个都没给，编译器找不着能用的构造函数。

### 6.4 组合的硬性质：是"抄一份"，不是"绑在一起"

这一条比构造顺序更容易错，因为它在**编译期完全看不出来**，只有运行起来才发现"我改的那本和我想的那本不是同一本"。

用两个类对比，代码在 `lesson02.cpp` 6.3 段：

```cpp
class ShelfA                    // 对象数组：三本书真住在里面
{
public:
    Book m_books[3];
    int  m_count;
    ShelfA() : m_count(0) {}
};

class ShelfB                    // 指针数组：只存三个地址，书还在外面
{
public:
    Book* m_books[3];
    int   m_count;
    ShelfB() : m_count(0)
    {
        for (int i = 0; i < 3; i++) m_books[i] = nullptr;
    }
};
```

三类证据，一个比一个硬。

**证据一：`sizeof` 就不一样。** 4.5 已经量过一遍 —— 练习版 `sizeof(Book)` 112、对象数组版 344、指针版 32，换个类名数字不动，这里不重复贴。

差在哪一句话说完：`ShelfA` 里三本书是**住进来**的，`3 × 112 + 4`（`m_count`）对齐成 344；`ShelfB` 里只有三个 8 字节的地址，`3 × 8 + 4` 对齐成 32。对象数组把书装进自己肚子里，指针数组只记住书在哪。

**证据二：成员地址落在容器内部。**

```text
ShelfA 对象自己的地址   : 000000286A5DE880
  sa.m_books[0] 的地址  : 000000286A5DE880   ← 和上面一模一样
  sa.m_books[1] 的地址  : 000000286A5E…       （比 [0] 大 112）
  [1] 和 [0] 差多少字节 : 112
```

`sa.m_books[0]` 的地址和 `sa` 本身**完全相同** —— 因为数组是类的第一个成员，它就长在对象最前面。`[1]` 在它后面 112 字节处，`[2]` 再后面 112。三本书首尾相接，全在 `sa` 这 344 字节里面。

而指针版本：

```text
外面那本书的地址        : 000000286A5DE440
  sb.m_books[0] 存的地址: 000000286A5DE440   ← 就是它
```

`sb.m_books[0]` 里存的值，正好等于外面那本书的地址。它指向的不是自己内部的存储，是另一个地方。

**证据三：改副本，原件不动。**

```cpp
Book outside("外部书", "某人", "ISBN-000", 66.0);
ShelfA sa2;
sa2.m_books[0] = outside;         // 抄一份进去
```

```text
指针那条 sb.m_books[0] 和 &outside 相等吗: 相等（指针存的同一本书的地址）
抄来的 sa2.m_books[0] 地址和 &outside 相等吗: 不相等（是另一个对象，只是内容一样）
```

内存长这样：

```text
组合：两本书，两份数据
┌─ outside ─────────────┐        ┌─ sa2 ──────────────────────┐
│ m_title  "外部书"     │        │ m_books[0]                 │
│ m_isbn   "ISBN-000"   │        │   m_title  "外部书"        │
│ m_price  66.0         │        │   m_isbn   "ISBN-000"      │
│ m_isBorrowed false    │        │   m_price  66.0            │
└───────────────────────┘        │   m_isBorrowed false       │
   ↑ 改这个                        └────────────────────────────┘
   sa2 里那份纹丝不动                  ↑ 改这个，outside 纹丝不动

指针：一本书，两个地址
┌─ outside ─────────────┐  ←────  sb.m_books[0]
│ m_title  "外部书"     │  ←────  other.m_books[0]
│ m_isBorrowed false    │
└───────────────────────┘
  改一次，两个持有者看到的是同一个改动
```

这就是组合的硬性质：**`User` 里的 `Book` 和外面那个 `Book` 是两个对象，内容相同，命运无关。** 组合是"复制一份数据进来"，不是"建立一个指向关系"。

任务 A 把这条性质直接打在作业上：

```text
把外面的 a1 改成已借出，看 stuA 里那本变不变：
  外面 a1 的状态:      已借出
  stuA 里记的那本:     可借   ← 没跟着变，因为是两个独立对象
```

### 6.5 落回你的作业：`BorrowRecord m_records[60]` 这个设计对不对

4.5 已经从"选哪个"的角度算过一遍账（对象数组省心、指针数组省空间，见 §4.5 的「那到底该用哪个」）。这里换个角度：**你 `User.h` 已经写好了，我只看它哪里有坑。**

先说结论：**你现在这个写法是对的，不用改成指针。** 组合是你的作业里唯一能不碰 `new` / `delete` 的方案，第三课之前你都该用它。

但 `User.h` 里有三处，等你写到 `borrowBook` 的时候一定会绊你。逐个说清。

**第一处：`void setBook(Book& book) { m_book = book; }` —— 这是拷贝，不是绑定。**

`User.h:9`。`m_book = book;` 执行的是 `Book` 的**拷贝赋值运算符**，把外面那本书的每个字段抄一份进 `m_book`。执行完，`m_records[k].m_book` 和外面那本书是两个对象。这就是 6.4 讲的那条硬性质，落在你作业里就是：

```cpp
Book b1("C++ Primer", "Lippman", "ISBN-001", 128.0);
user.borrowBook(b1);            // 里面调 setBook(b1)，抄一份
b1.setIsBorrowed(true);         // 改外面这本
user.displayRecords();          // 里面那份还是"可借"
```

参数写 `Book&` 而不是 `const Book&`，是因为 `setBook` 只是读 `book`、不写它 —— 按理说该写 `const Book&`（第五节）。但 `borrowBook` 是要改 `b1` 状态的，所以 `borrowBook(Book& book)` 这个非 const 参数**是对的**，别改。这两层签名不冲突：`borrowBook` 收可改引用因为要改它，`setBook` 收可改引用但其实只读 —— 后者可以收紧成 `const Book&`，收紧之后编译一样过。

**第二处：`Book getBook() { return m_book; }` —— 返回值，不是引用。**

`User.h:10`。这是你这几个函数里最容易踩的一个坑，因为它的错误**不会报错，只是悄悄没用**：

```cpp
user.getBook().setIsBorrowed(true);      // 看起来改了
// 实际上：getBook() 返回一个临时 Book 副本，
// setIsBorrowed 改的是这个临时对象，
// 语句结束，临时对象销毁 —— 什么都没发生
```

编译通过，运行不崩，数据没变。这种 bug 你查半小时都找不出来。

为什么不能改成 `Book& getBook() { return m_book; }`？能改，而且能解决上面这个问题。但那样一来，任何拿到 `getBook()` 的人都能改你 `User` 内部的私有数据 —— 封装就漏了。所以标准做法是：

```cpp
const Book& getBook() const { return m_book; }     // 给看不给改
```

然后如果真的需要改状态，让 `User` 自己提供方法（正是你的 `borrowBook` / `returnBook` 该干的事），而不是把内部的 `Book&` 交出去。

**第三处：`BorrowRecord m_records[60]` 这个 60，和 `m_maxnum` 是两套数。**

`User.h:19-20` 里 `m_maxnum` 是可以设的上限（构造时传进来），`m_records[60]` 是数组的物理容量。这两个必须满足 `m_maxnum <= 60`，否则 `m_records[m_borrownum]` 就越界。

现在的写法里没有任何地方检查这件事 —— `User(string name, string id, int borrownum, int maxnum)` 允许你传 `maxnum = 200`。建议在构造里加一道：

```cpp
User::User(string name, string id, int borrownum, int maxnum)
{
    m_name      = name;
    m_id        = id;
    m_borrownum = borrownum;
    m_maxnum    = (maxnum > 60) ? 60 : maxnum;    // 顶多到数组容量
}
```

顺便说清 `m_borrownum` 和 `m_maxnum` 的分工，这两个很容易混：

| 字段 | 含义 | 谁改它 |
|------|------|--------|
| `m_borrownum` | **现在**借了几本（0 ~ m_maxnum） | `borrowBook` 加一，`returnBook` 减一 |
| `m_maxnum` | **最多**能借几本（策略，一般不动） | 构造时定，之后不该改 |

判断"能不能再借"用的是 `m_borrownum >= m_maxnum`，不是 `m_borrownum >= 60`。60 是墙，`m_maxnum` 是规则，撞规则给提示，撞墙就是内存事故。

**第四处（不算错，但要心里有数）：`User` 对象有多大。**

`sizeof(User)` 我实测过：**10632 字节，即 10.4KB**。算法是 60 × 176（项目版 `Book`）= 10560，加姓名、学号两个 `string`（各 32 字节）和 `m_borrownum`、`m_maxnum` 两个 `int`，再按 8 字节对齐。你在 `main` 里写 `User u;` 这一行，就是在栈上开了 10.4KB。栈默认 1MB = 1048576 字节，`1048576 ÷ 10632 ≈ 98` —— 也就是说你声明第 99 个 `User` 时程序直接崩，报"栈溢出"，一个变量都还没赋值。

现在作业里就一两个 `User`，完全没问题。但你要知道这个数字从哪来：**组合的代价就是对象变大**。指针版本 `BorrowRecord* m_records[60]` 只占 480 字节，书在堆上，但那要你自己 `new` / `delete` —— 第三课的内容。

一句话收尾：**这一章你继续用组合，别换指针。** 你现在遇到的"我改了副本，真书没变"不是设计错了，是组合的固有性质，你的作业本来就该靠"手动同步两边状态"来解 —— 第十节任务 C 的 `borrowBook` 里那行 `book.setIsBorrowed(true)` 干的就是这件事。

## 七、依赖：把 `borrowBook` / `returnBook` 彻底写对


### 7.1 先把话说明白：本章有两套名字，别抄错

前面几节为了方便，用的是一个只有三格记录的练手类。你项目里的 `User` 不是那个样子。两份代码长得像，名字不一样，直接搬会撞车。

先把对照表摆出来，后面所有代码一律用**右边这一列**（你项目里的真名）：

（第一、二节演示值传递用的还有一个更简的 2 参版 `Book`，只活在开头那几个例子里，没列进这张表 —— 它的来历见第一节顶部。表里这两列才是你后面真正要抄的。）

| 练手版里的写法 | 你项目里的真名（`User.h` / `User.cpp`） |
|---|---|
| `m_count` | `m_borrownum` |
| `m_maxnum` 上限 3，数组也开 3 格 | `m_maxnum` 由构造参数给（项目里是 3），数组固定开 **60** 格 `BorrowRecord m_records[60]` |
| `m_records[i].m_date`（借书日期字段） | **不存在**。`BorrowRecord` 只有 `Book m_book` 一个成员 |
| `m_records[i].m_book.getIsbn()` | `m_records[i].getBook().getISBN()`（注意是大写 ISBN） |
| `Book(string title, string author, string isbn, double price)` —— 4 个参数 | `Book(string title, string author, string publisher, string ISBN, string id, double price, bool isBorrowed)` —— 7 个参数（`Book.h:19-21`） |
| `Book` 里是 3 个 `string` + 1 个 `double` + 1 个 `bool`，`sizeof(Book)` = 112 | `Book` 里是 5 个 `string` + 1 个 `double` + 1 个 `bool`，`sizeof(Book)` = 176 |
| `bool borrowBook(...)` | `void borrowBook(Book& book);`（`User.h` 第 34 行） |
| `bool returnBook(...)` | `void returnBook(Book& book);`（`User.h` 第 35 行） |

这张表只管**名字怎么换**。另有一条判断规则不在表里：确认"是不是同一本"时用 `getId()`，别用 `getISBN()` —— 理由见 5.5 那张 ISBN / id 分工表，后面 7.2、7.3 的代码也都按 `getId()` 写。

两条纪律，先刻在脑子里：

1. **抄代码之前先看签名。** 返回类型也算签名的一部分。`User.h` 里写的是 `void`，你在 `User.cpp` 里写成 `bool`，编译器当场甩出三条：

```text
error C2556: “void User::borrowBook(Book &)”: 重载函数与“bool User::borrowBook(Book &)”只是在返回类型上不同
error C2371: “User::borrowBook”: 重定义；不同的基类型
error C2084: 函数“bool User::borrowBook(Book &)”已有主体
```

三条一起冒出来，是因为编译器先把 `void` 和 `bool` 两版当成"只差返回类型的重载"，而 C++ 不承认这种重载 —— 它认不出你到底想留哪一个。改法只有一条：让声明的返回类型和定义的一模一样。
2. **上限和容量是两件事。** `m_maxnum` 是"他最多能借几本"（运行时决定，可能是 3、可能是 5），`m_records[60]` 是"这张表物理上能放几格"（编译期定死）。两个数字必须各管各的，绝不能拿一个当另一个用。

### 7.2 `borrowBook`：三道闸全过才放行

借书这件事，成功需要三个条件**同时**成立：

- **闸 1**：他自己没借满（`m_borrownum < m_maxnum`）；
- **闸 2**：他自己没借过这本书（不能同一本借两遍）；
- **闸 3**：这本书在书库里是"可借"的（没被别人借走）。

闸 2 和闸 3 的顺序不能调：**先查"他自己借过没有"，再查"被别人借走没有"。** 因为自己借走的那本书，状态也是"已借出" —— 顺序反了，第二次借同一本会被报成"这本书已经被别人借走了"，话是错的，看日志的人会以为系统出鬼了。

任何一道没过，就一个字都不能改 —— 包括 `m_borrownum`、`m_records`、`book` 的状态，三样都得原封不动。这叫**先判断、后动手**。
下面是能直接替换进 `User.cpp` 的完整版本：

```cpp
bool User::borrowBook(Book& book)
{
	// 闸 1：额度
	if (m_borrownum >= m_maxnum)
	{
		cout << "借书失败：你已经借满 " << m_maxnum << " 本了。" << endl;
		return false;
	}

	// 闸 2：他自己是不是已经借过这本（按馆内编号 id 认书，理由见 5.5）
	for (int i = 0; i < m_borrownum; i++)
	{
		if (m_records[i].getBook().getId() == book.getId())
		{
			cout << "借书失败：你已经借过《" << book.getTitle() << "》了。" << endl;
			return false;
		}
	}

	// 闸 3：这本书在书库里是不是已经被别人借走了
	if (book.getIsBorrowed())
	{
		cout << "借书失败：《" << book.getTitle() << "》已经被别人借走了。" << endl;
		return false;
	}

	// 三道闸全过了，才动状态。两边必须一起改，不能只改一边
	m_records[m_borrownum].setBook(book);   // ① 抄一份进记录表
	m_borrownum++;                          // ② 借书数加一
	book.setIsBorrowed(true);               // ③ 书库里那本书标成已借出

	cout << "借书成功：《" << book.getTitle() << "》" << endl;
	return true;
}
```

**配套改 `User.h` 第 34 行**（不改就编译不过，`C2556`）：

```cpp
	bool borrowBook(Book& book);
```

`LibrarySys.cpp` 第 108 行 `user.borrowBook(books[idx]);` 不需要动 —— 返回值扔掉了，语法上完全合法。

> **万一老师要求返回 `void`**：把 `bool` 改回 `void`，把两处 `return false;` 和末尾的 `return true;` 删掉，三道闸的判断逻辑一个字都不用动。返回值只是顺手告诉调用方"成了没有"，借书这件事本身不靠它。答辩被问到"为什么用 `bool`"，就答：**三道闸有三条不同的失败原因，`void` 会把它们全丢进 `cout` 里，调用方想根据结果做别的事就做不到**。

逐句说清 ①②③ 为什么缺一不可：

- 少了 ①，书库里标成"已借出"，但他自己的记录里查不到这本书 —— 他还书时按馆内编号找不到，永远还不掉。
- 少了 ②，记录写了进去，但计数还是 0 —— 下一次借书会**覆盖同一格**，前一本凭空消失。
- 少了 ③，记录和计数都对，但书库那边不知道这本书出去了 —— 下一个人还能再借一遍，两个人同时"拥有"同一本。

这三行就是这一章的核心动作：**一份事实（这本书被谁借走了）在两个地方（书库对象、学生记录）各存一份，改的时候必须两手一起改。**

### 7.3 `returnBook`：先认人，再删记录，最后解锁

还书比借书多一步麻烦：**你得先确认"你还的这本，是不是他手上真有的那本"**。这一步不做，整个系统会烂掉（7.5 节缺陷 3 会演给你看）。

完整版本，可直接替换：

```cpp
bool User::returnBook(Book& book)
{
	// 闸 1：他手上到底有没有书
	if (m_borrownum <= 0)
	{
		cout << "还书失败：当前没有任何借阅记录。" << endl;
		return false;
	}

	// 闸 2：这本是不是他借过的那本 —— 按馆内编号在记录表里找
	int pos = -1;
	for (int i = 0; i < m_borrownum; i++)
	{
		if (m_records[i].getBook().getId() == book.getId())
		{
			pos = i;
			break;
		}
	}
	if (pos == -1)
	{
		cout << "还书失败：你没有借过《" << book.getTitle() << "》。" << endl;
		return false;
	}

	// 找到位置 pos 了。从 pos 开始，把后面每一格往前挪一格
	for (int i = pos; i < m_borrownum - 1; i++)
	{
		m_records[i] = m_records[i + 1];
	}
	m_borrownum--;

	// 尾巴上空出来的那一格清掉，避免残留一份旧副本
	m_records[m_borrownum] = BorrowRecord();

	// 最后才解锁书库里那本书
	book.setIsBorrowed(false);

	cout << "还书成功：《" << book.getTitle() << "》" << endl;
	return true;
}
```

**配套改 `User.h` 第 35 行**：

```cpp
	bool returnBook(Book& book);
```

`LibrarySys.cpp` 第 123 行 `user.returnBook(books[idx]);` 同样不用动。

#### 为什么要"前移一格"，不能只把计数减一

这是本章最容易做错的一步。记录表是一段**连续**的数组，`m_borrownum` 既表示"借了几本"，也表示"下一个空位在哪一格"。这两个含义只有在**从尾部删除**时才一致；要从中间删一本书，就必须有人把数组重新压紧。

拿 `m_borrownum = 3`、借的是 A、B、C，现在要还 A（下标 0）举例：

```
还之前（m_borrownum = 3）：
  下标：      [0]        [1]        [2]
  内容：       A          B          C
               ↑ 要还的是下标 0

前移（i 从 pos=0 走到 m_borrownum-2=1）：
  i=0：m_records[0] = m_records[1]  →   B          B          C
  i=1：m_records[1] = m_records[2]  →   B          C          C

m_borrownum--  →  2
清尾巴：m_records[2] = BorrowRecord()  →   B          C        （空）

结果：表里躺着 B、C，正好是他手上剩下的两本。
```

一句话记住：**循环变量从 `pos` 开始，条件是 `i < m_borrownum - 1`，循环体是"后一格抄到前一格"。** 三个地方错一个就漏一格或者越界。

#### 改完以后，现象差在哪

同一段场景（借 A、借 B、还 A、再借 C）跑一遍：

**改之前**：借书全程一声不吭（成功路径一句打印都没有），还完 A 之后表里还是 A、C，而他手上明明是 B、C。

**改之后**：

```
--- 借 A ---
借书成功：《C++ Primer》
--- 借 B ---
借书成功：《算法导论》
--- 还 A ---
还书成功：《C++ Primer》
--- 再借 C ---
借书成功：《Effective C++》

当前 m_borrownum = 2
第 1 本: 算法导论
第 2 本: Effective C++
书库里三本书的状态：
  A C++ Primer = 可借
  B 算法导论 = 已借出
  C Effective C++ = 已借出
```

记录显示的两本，和书库显示"已借出"的两本，对上了。**"能对上"就是这段代码合格的标准。**

#### 缺陷 1：`Book` 的带参构造函数把 `isBorrowed` 形参丢了

**错在哪一行** —— `Book.cpp` 第 18～27 行。整个函数长这样：

```cpp
Book::Book(string title, string author, string publisher, string ISBN, string id, double price, bool isBorrowed)
{
	m_title = title;
	m_author = author;
	m_publisher = publisher;
	m_ISBN = ISBN;
	m_id = id;
	m_price = price;
	m_isBorrowed = false;      // ← 第 26 行：坏在这里
}
```

一句话点破：**函数头上接了一个 `isBorrowed`，函数体里从头到尾没读过它一次，反而把成员写死成 `false`。** 外面传什么进来都会被踩掉。

**会出什么后果** —— 一切"构造时就该带状态"的书全都变成"可借"。走一遍：

```cpp
Book b("C++ Primer", "Stanley Lippman", "电子工业出版社", "9787121358579", "B001", 128.0, true);
cout << b.getIsBorrowed();     // 期望 1，实际打 0
```

状态在构造这一步就被丢掉了，后面无论怎么改都补不回来。数据流是这样的：

```
调用：  Book b(..., true)
                 │
                 ▼
形参：  bool isBorrowed = true        ← 收下了，放在栈上
                 ╳                    ← 没有任何一条语句把它读出来
成员：  bool m_isBorrowed = false     ← 直接被写成常量 false
```

**这个缺陷最阴的地方**：你项目里 `LibrarySys.cpp` 第 145～147 行 push_back 那三本书，传进去的都是 `false`，所以改之前和改之后跑起来**看不出任何区别**。没有一行输出会变，没有一个功能会坏。它要到"以后加一个从文件读入已借出图书"的功能时才会爆。

也就是说：**你现在的测试用例根本测不到它**。这类缺陷只能靠"读代码 + 对照签名"抓出来，靠运行抓不出来。

**为什么会出这个错** —— 把"形参"和"成员"当成同一个东西了。

`bool isBorrowed` 是函数进门时接的一个包裹，函数一返回就没了；`m_isBorrowed` 是对象身上的柜子，活得比函数长。这两者之间**没有任何自动通道**，必须由你亲手写一行 `m_isBorrowed = isBorrowed;` 才能把包裹放进柜子。

这和第二节讲"参数怎么进函数"是同一件事，只是方向反过来：

- 借书、还书那种**成员函数**，方向是"里面的改动要传出去" → 用引用（`Book&`），改的是本体；
- **构造函数**，方向是"外面的值要传进来" → 用赋值或初始化列表，把形参抄进成员。

同一个参数通道，两个方向，两个方向都**不会自动**。这就是零基础最容易漏的一环：以为"参数传进来了就等于成员有值了"。

**改成什么** —— 只改第 26 行，一个词：

```cpp
Book::Book(string title, string author, string publisher, string ISBN, string id, double price, bool isBorrowed)
{
	m_title = title;
	m_author = author;
	m_publisher = publisher;
	m_ISBN = ISBN;
	m_id = id;
	m_price = price;
	m_isBorrowed = isBorrowed;     // 形参 → 成员，唯一的一行
}
```

**注意不要顺手把默认构造函数的第 14 行也改了。** `Book.cpp` 第 6～15 行是默认构造函数 `Book::Book()`，它**没有** `isBorrowed` 这个形参，那里写 `m_isBorrowed = false;` 是**对的**。两个函数里都有 `m_isBorrowed = false;` 这一行文本，改错一个就编译不过（`isBorrowed` 未声明，`C2065`）。

改完的现象差别：`Book b(..., true).getIsBorrowed()` 从 `0` 变成 `1`。你现在的命令行程序一切如常 —— 因为它本来就只传 `false`。

#### 缺陷 2：`returnBook` 只把计数减一，没把记录从数组里挪走

**错在哪一行** —— `User.cpp` 第 96～107 行：

```cpp
void User::returnBook(Book& book)
{
	if (m_borrownum <= 0)
	{
		cout << "当前没有借书记录，无法还书。" << endl;
		return;
	}
	book.setIsBorrowed(false);                                  // 第 104 行
	m_borrownum--;                                              // 第 105 行
	cout << "还书成功：" << book.getTitle() << endl;
}
```

一句话点破：**第 104 行和第 105 行之间，本该有"把这一格从数组里删掉、后面整体前移"的代码，但一行都没有。** 计数减了，表没动。

**会出什么后果** —— 记录表会越来越歪，最后歪到"表里的书"和"手上的书"完全是两批。

具体走一遍：借 A（C++ Primer）、借 B（算法导论）、还 A、再借 C（Effective C++）。

| 时刻 | `m_borrownum` | `[0]` | `[1]` | `[2]` |
|---|---|---|---|---|
| 起点 | 0 | 空 | 空 | 空 |
| 借 A | 1 | **A** | 空 | 空 |
| 借 B | 2 | A | **B** | 空 |
| 还 A | 1 | **A ← 没删掉！** | B | 空 |
| 再借 C | 2 | A ← 幽灵 | **C ← 把 B 覆盖了** | 空 |

这是真的跑出来的结果（用你现在的源码，一点没改）：

```
--- 借 A ---
--- 借 B ---
--- 还 A ---
还书成功：C++ Primer
--- 再借 C ---

当前 m_borrownum = 2
第 1 本: C++ Primer
第 2 本: Effective C++
书库里三本书的状态：
  A C++ Primer = 可借
  B 算法导论 = 已借出
  C Effective C++ = 已借出
```

对着看：**他手上拿的是 B（算法导论）和 C（Effective C++），表里却写着 A 和 C。**

三重崩：

1. `displayRecords()` 打出来的名单是假的 —— 显示 A，实际 A 已经在书架上；
2. B 明明借走了，记录里**查不到**，他没法通过记录证明自己借过 B；
3. 新借的 C 写进了本该属于 B 的那一格，B 的记录被物理覆盖 —— 不是"丢失引用"，是整个副本被 `operator=` 盖掉，找不回来了。

**为什么会出这个错** —— 一个变量背了两个含义，删了中间一个，两个含义就分家了。

`m_borrownum` 同时表示：

- 借了几本（**数量**）；
- 下一个空位在第几格（**位置**）。

只要永远从末尾追加、从末尾删除，这两个含义永远相等，一个变量够用。可一旦从**中间**删掉一本，数量减了一、位置没变，两个含义立刻分家。这段代码只做了"数量减一"，忘了"位置也要跟着压紧"。

往概念层接：**组合的代价就在这里。** `User` 拥有一个 `Book` 数组（`m_records[60]`），"拥有"意味着这个数组的一致性**由你自己负责**。C++ 不会帮你在删元素时自动压缩数组 —— 那是 `std::vector` 干的活（第五课会讲），普通数组不会。

所以组合不是"把两个类放一起"，而是"你接手了一份数据，你就得自己维护它的每一处不变量"。这里的不变量只有一句：**`m_records[0]` 到 `m_records[m_borrownum-1]` 这连续的一段，必须一格不漏地对应他手上的每一本书。**

**改成什么** —— 完整的 `returnBook`（代码见 7.3 节，包含按馆内编号认人 + 前移 + 清尾）。连带要改 `User.h` 第 35 行的返回类型。

改完那同一段场景的输出变成 `第 1 本: 算法导论 / 第 2 本: Effective C++` —— 和他手上的两本完全一致。

#### 缺陷 3：还书不检查"还的是不是他借的那本"

**错在哪一行** —— 还是 `User.cpp` 第 104 行：

```cpp
	book.setIsBorrowed(false);      // 无条件执行：随便传一本进来都会解锁
```

整个函数唯一的前置检查是第 99 行的 `if (m_borrownum <= 0)` —— 那是在数**他有没有书**，不是在认**你手上这本是不是他的**。数量对得上就放行，这是缺陷。

一句话点破：**`returnBook` 收了别人的一本书，连"这是不是他借过的"都不问，直接解锁、直接扣额度。**

**会出什么后果** —— 两种，第二种能把书永久锁死。

**后果一：冤枉一本无辜的书。** 如果传进来的是书库里正被别人借着的 B，`B.setIsBorrowed(false)` 一执行，B 在系统里就变回"可借"了 —— 但 B 还在别人手上。下一个人来借 B，闸 2 通过，成功借出。**现在两个人同时"拥有"B，而系统认为只有一个人。**

**后果二：把一本书永久锁死。** 这是最狠的一种。走一遍：他只借了 A，然后错误地还了一本没借过的 D。

```
借完 A：m_borrownum = 1，A 的状态 = 已借出
还书成功：从没借过的书
错误地还了 D：m_borrownum = 0，A 的状态 = 已借出

--- 现在他再想借 A ---
This book is borrowed.
--- 他想把 A 还掉，好解锁 ---
当前没有借书记录，无法还书。

最终：m_borrownum = 0，A 的状态 = 已借出
暂无借阅记录。
```

（这段也是真跑出来的。）看清楚这个死锁：

- 他还想借 A → 闸 2 拦：`book.getIsBorrowed()` 是 `true`，报 `This book is borrowed.`；
- 他想干脆把 A 还掉解锁 → 第 99 行 `m_borrownum <= 0` 成立，**函数在碰任何东西之前就 return 了**；
- 最后：`m_borrownum = 0`，A 状态"已借出"，记录表空的。

**A 从此锁死：借不了、还不了、记录里没有、书架上也没有。** 除了重启程序（内存清零），没有任何操作能把它救回来。这就是缺陷 2 和缺陷 3 叠加之后的真实破坏力 —— 不是"数据有点脏"，是**这本书在系统里彻底消失了，而且它占着一个"已借出"的位置永久不还**。

**为什么会出这个错** —— 把"引用"当成了"身份"。

`Book& book` 这个参数的意思是"我手上有一个 Book 对象，我用引用把它交给你，你能直接改它"。它只保证**能改**，不保证**改得对**。引用是一把能开门的钥匙，但开门之前得先抬头看一眼门牌号 —— 这扇门是不是你要开的那扇。

依赖关系的纪律就在这句：**对方是谁，必须由你自己核对。引用不会替你核对，类型系统也不会。** `Book&` 只说"这是本合法的书"，不说"这是这个学生借的那本"。

**改成什么** —— 加按馆内编号查表那一段（7.3 节的闸 2），找到 `pos` 才往下走，找不到就打印"你没有借过《X》"并 `return false`。

改完的现象差别：错误地还 D 时，一行 `还书失败：你没有借过《从没借过的书》`，而且 `m_borrownum` **停在 1 不动**，A 的状态**还是已借出** —— 因为什么都没被改。死锁不会再发生。

#### 另外还有第四处：`Book::display()` 里的空 `if`

Lead 让我确认"到底是不是三处"。我读完了四个文件，**逻辑缺陷是三处**，但还有一处明显的半成品，性质不同，单独列出来。

**错在哪一行** —— `Book.cpp` 第 110～113 行：

```cpp
	if (m_isBorrowed)
	{
		//（视频中未完成：此处可输出"已借出"状态）
	}
```

一句话点破：**条件判断写好了，`if` 体里一个字都没有，状态算对了却不打印。**

**会出什么后果** —— 每个直接调用 `book.display()` 的地方，都看不到这本书的借阅状态。你现在之所以没觉得缺，是因为 `LibrarySys.cpp` 第 61 行在 `display()` 之外又补打了一行：

```cpp
	cout << "状态: " << (books[i].getIsBorrowed() ? "已借出" : "可借")
```

相当于在门外另贴了一张纸条。功能上看起来正常，但 `Book::display()` 自己是不完整的 —— 答辩时老师点开这个文件，一眼就能看见一个空 `if` 和一行"视频中未完成"的注释，这是直接扣分的。

**为什么会出这个错** —— 这不是设计错误，是**没写完**。但它值得单独说，因为它属于"状态同步"链条上的第三环：

1. 状态算对（`m_isBorrowed` 值是对的）；
2. 状态存对（存在对象里）；
3. **状态被看见**（能打印出来）。

前两环对了、第三环断了，对使用者来说和"没有这个状态"是一样的。**系统里"没人知道"和"不存在"，是一回事。**

**改成什么** —— 一行：

```cpp
	if (m_isBorrowed)
	{
		cout << "（已借出）";
	}
	else
	{
		cout << "（可借）";
	}
```

改完注意一个副作用：`LibrarySys.cpp` 第 61 行会再打一遍状态，你的输出会变成 `… （可借） 状态: 可借` 这种重复。要么把第 61 行那行删掉（让 `display()` 全权负责），要么保留重复但知道它为什么重复。**不要两边各改一半，改完自己跑一遍看输出对不对。**

### 7.5 这三处错误的共同点

一句话：**它们全都是"同一份事实在两个地方各存一份，改的时候只改了一边"的变种。**

把它们摊在一条时间轴上，你能看见这是同一个病在四个不同环节发作：

| 环节 | 事实是什么 | 哪边没同步 | 对应 |
|---|---|---|---|
| 进门 | "这本书是不是已借出" | 形参收下了，成员没接住 | 缺陷 1（`Book.cpp:26`） |
| 出去（借） | "这本书归他了" | 记录改了、计数改了、书库没改（或反之） | 7.2 节 ①②③ |
| 回来（还） | "这本书回到书架了" | 计数减了、数组没删 | 缺陷 2（`User.cpp:104-105`） |
| 认人 | "还的是他借的那本吗" | 根本没核对，改了别人的书 | 缺陷 3（`User.cpp:104`） |
| 被看见 | "系统里这本书什么状态" | 状态有了，没打印 | 第四处（`Book.cpp:110-113`） |

这一章讲"组合与依赖"，听起来像在讲怎么把两个类放一起。不是的。真正的纪律是这一句：

**只要同一份事实存在两个副本（书库里的 `m_isBorrowed`、学生记录里的 `m_book` 副本、计数 `m_borrownum`），你就必须为"它们永远一致"负责。C++ 不会替你做，编译器也不会提醒你 —— 因为它根本不知道这两份数据说的是同一件事。**

这就是为什么这三处缺陷全都编译通过、全都不报警告、全都"看起来能跑"。它们不是语法问题，是**你在心里要维护的那张一致性清单**没维护住。

写下一个成员函数之前，先问自己三句话：

1. 这个动作会动到哪几份数据？（列出来）
2. 每一份都改到了吗？（逐个数）
3. 如果中途有一份改不了（比如闸 2 拦住了），前面已经改的那些要不要退回去？

第三问就是"先判断、后动手"的由来 —— 判断全做完再动手，就不存在"改了一半要回滚"的问题。

### Q1（官方思考题）组合类构造函数的调用过程是怎样的？请打断点观察

**老师问什么**

"`User` 里面有一个 `BorrowRecord` 数组，`BorrowRecord` 里面有一个 `Book`。那么创建一个 `User` 对象的时候，`Book` 的构造函数什么时候被调用？谁先谁后？"

**标准答案（可直接背）**

分四步，顺序固定：

1. **分配内存**：`User` 对象需要的那块内存（含 `m_records` 数组的 60 格、每格里的那个 `Book`）一次性分配好。这一步不调用任何构造函数。
2. **构造成员**：按成员在类里**声明的顺序**，逐个构造。`m_name`（`string`）→ `m_id`（`string`）→ `m_borrownum`（`int`）→ `m_maxnum`（`int`）→ `m_records[60]`（每个元素里的 `Book` 依次默认构造 60 次）。**注意：只有声明顺序说了算，和你在初始化列表里写的先后无关。**
3. **执行构造函数体**：`{ ... }` 里面的语句。
4. 对象构造完成，返回。

析构严格**逆序**：先执行析构函数体，再按声明的**反序**销毁成员（`m_records` → `m_maxnum` → `m_borrownum` → `m_id` → `m_name`）。

**能直接粘进 Visual Studio 打断点的代码**

新建一个空项目，粘这段进去（不依赖你的项目文件，单独跑）：

```cpp
#include <windows.h>
#include <iostream>
#include <string>
using namespace std;

class Item
{
public:
	string m_tag;
	Item() { m_tag = "(默认)"; cout << "  Item 默认构造: " << m_tag << endl; }
	Item(const string& t) : m_tag(t) { cout << "  Item 带参构造: " << m_tag << endl; }
	~Item() { cout << "  Item 析构: " << m_tag << endl; }
};

class Holder
{
private:
	string m_name;
	Item   m_first;
	Item   m_second;
	int    m_count;
public:
	// 注意：初始化列表里故意把 m_second 写在 m_first 前面
	Holder(string name) : m_name(name), m_second("second"), m_first("first"), m_count(0)
	{
		cout << "  Holder 构造函数体" << endl;
	}
	~Holder() { cout << "  Holder 析构函数体" << endl; }
};

int main()
{
	SetConsoleOutputCP(65001);
	cout << "--- 进入作用域 ---" << endl;
	{
		Holder h("H");
		cout << "--- 作用域结束 ---" << endl;
	}
	cout << "--- 已离开 ---" << endl;
	return 0;
}
```

**逐行说明：断点停在哪、盯哪个变量、会看到什么**

**第一轮：在 `Item` 的带参构造函数里打断点。**

把光标放在 `Item(const string& t) : m_tag(t) { ... }` 这一行，按 `F9` 下一个红点，然后 `F5` 启动。

- 程序会**第一次**停在这个红点上。这时看屏幕下方的**调用堆栈（Call Stack）**窗口，从上到下是：

  ```
  Item::Item(const std::string &)      ← 当前停在这里
  Holder::Holder(std::string)          ← 调用者
  main()                               ← 再上一层
  ```

- **这就是铁证**：停在这一行的时候，`main` 还什么都没干，`Holder` 的构造体 `{ cout << ... }` 也还没执行 —— 但 `Item` 的构造函数已经在跑了。也就是说：**成员对象的构造，发生在 `Holder` 函数体之前。**
- 看"自动窗口（Autos）"里的 `t`，值是 `"first"`。注意初始化列表里写的是 `m_second("second")` 在前，可先停下来的却是 `first` —— **构造顺序只由声明顺序决定**（`m_first` 声明在 `m_second` 前面），初始化列表怎么写都不影响。
- 按 `F5` 继续，第二次停在同一个断点，`t` 的值是 `"second"`。再按 `F5`，不会再停第三次 —— 两个 `Item` 成员都构造完了。

**第二轮：在 `Holder` 构造函数体里打断点。**

把红点挪到 `cout << "  Holder 构造函数体" << endl;` 这一行。

- 停住的时候，在"自动窗口"里展开 `this`，能看到：
  - `m_name` = `"H"`
  - `m_first.m_tag` = `"first"` ← **已经有值了**
  - `m_second.m_tag` = `"second"` ← 已经有值了
  - `m_count` = `0`
- 关键观察：**这个断点绝不会在 `Item` 构造之前停下来。** 你按多少次 `F5` 都一样 —— `Holder` 的函数体永远排在所有成员构造之后。这就证明了"函数体是最后一步"。

**第三轮：在 `~Holder()` 和 `~Item()` 里各打一个断点。**

按 `F5` 让作用域结束，你会看到停止顺序是：`~Holder()` 函数体 → `~Item()`（`m_second`，值 `"second"`）→ `~Item()`（`m_first`，值 `"first"`）。**和构造顺序完全相反。**

完整的运行输出长这样（我是真跑出来的）：

```
--- 进入作用域 ---
  Item 带参构造: first
  Item 带参构造: second
  Holder 构造函数体
--- 作用域结束 ---
  Holder 析构函数体
  Item 析构: second
  Item 析构: first
--- 已离开 ---
```

**加分一句**

"如果某个成员没有出现在初始化列表里，它并不会'不构造' —— 它会用**默认构造函数**构造一次，然后在构造函数体里被你赋一次值，等于白干一次。所以能在初始化列表里写的，就不要拖到函数体里赋值。对我们项目的 `User` 来说，`m_records[60]` 这 60 个 `Book` 一定会被默认构造 60 次，哪怕你后面一本都不借 —— 这就是固定数组的代价。"

### Q2（官方思考题）值传递和地址传递的区别是什么？分别适用什么场景？

**老师问什么**

"你写 `void f(Book b)` 和 `void f(Book& b)`，除了少打一个 `&`，还有什么区别？什么时候用哪个？"

**标准答案（可直接背）**

区别只有一个，但后果很硬：**值传递会复制一份新对象，函数里改的是副本；引用传递不复制，函数里改的就是本体。**

用地址一看就明白（`lesson02.exe` 的真实输出）：

```
  书库那本书的地址 = 000000168ECFF2A0

  [1a] 值传递：passByValue(lib)
    函数内副本的地址   = 000000168ECFF250     ← 和上面不一样，是另一个对象
  调用后书库那本书状态 = 可借                 ← 没变，改的是副本

  [1b] 引用传递：passByRef(lib)
    函数内引用的地址   = 000000168ECFF2A0     ← 和上面完全一样
  调用后书库那本书状态 = 已借出               ← 变了，改的就是本体
```

适用场景，一句话分工：

- **要改本体 → 用引用**（`Book&`）。项目的 `borrowBook(Book& book)`、`returnBook(Book& book)` 都是这一类，因为它们必须把 `m_isBorrowed` 改到书库那本书身上。
- **只读，不想复制 → 用 const 引用**（`const Book&`）。大对象（含 `string` 成员的 `Book` 有 7 个字段）复制一次要真拷贝所有 `string`，代价不小；`const Book&` 既不复制也不许改。
- **要改，但传的是指针 → 用指针**（`Book*`）。需要表达"可能没有这本书"（传 `nullptr`）时才用。日常能不用就不用，多一层解引用多一处空指针风险。
- **小类型（`int`、`double`、`char`）→ 直接值传递**。复制一个 `int` 就 4 字节，比传引用还便宜，没必要绕。

**加分一句**

"引用在底层就是一个自动解引用的常量指针 —— `sizeof(Book&)` 是 8，和 `sizeof(Book*)` 一样。所以引用的好处不是'不占空间'，是'不会空、不用写 `*`、语法上当作本体用'。另外 C++ 里引用一旦绑定就不能改绑，`Book& r = a; r = b;` 不是让 `r` 改指 `b`，而是把 `b` 的内容赋给 `a` —— 这个坑第八章会再踩一次。"

### Q3 `User` 和 `Book` 之间，到底是组合还是依赖？

**老师问什么**

"你这张 UML 图里，`User` 到 `Book` 画的是实心菱形还是虚线箭头？为什么？"

**标准答案（可直接背）**

**两种关系同时存在，但落点不同：**

- `User` → `BorrowRecord` → `Book`：`BorrowRecord` 里有一个 `Book m_book;` 成员 —— 是**按值拥有的真对象**，这部分形式上像组合（`User` 拥有记录，记录拥有一本 `Book` 的副本）。
- 但业务上，`User` 并**不拥有**书库里那本书。那本书是 `LibrarySys` 里的 `Book` 对象，`User` 借它只是"临时用到"。所以 `User` 对**书库里的** `Book` 是**依赖**关系。

一个更精确的说法：**`User` 依赖书库里的 `Book` 对象（借的时候通过 `Book&` 拿到它），同时在自己的记录表里存了它的副本（组合关系）。** 前者是"用"，后者是"存"。

**加分一句**

"判断标准就一句话：**生命周期归谁管。** 如果 `User` 死了这本书就该没了，那是组合；如果 `User` 死了书架上这本书还在，那是依赖。我们项目里 `User` 死了书当然还在 —— 所以我们**没有**真的'拥有'书，只拥有书的一份复印件。这个区别在第七节缺陷 2 里就要了命：复印件归你管，你得自己维护它。"

### Q4 `const Book&` 和 `Book&` 到底差在哪，我该用哪个？

**老师问什么**

"`getBook()` 为什么返回 `Book` 而不是 `Book&`？`setBook(Book& book)` 为什么参数不是 `const Book&`？"

**标准答案（可直接背）**

`Book&` 和 `const Book&` 的区别是**写权限**：

| 写法 | 能读 | 能改 | 能接受 `const Book` 类型的实参 |
|---|---|---|---|
| `Book&` | 能 | 能 | **不能**（报 `C2664`） |
| `const Book&` | 能 | **不能** | 能 |
| `Book`（值） | 能 | 能（改的是副本） | 能（复制一份） |

所以规则很简单：**函数里要改本体 → `Book&`；只读 → `const Book&`。**

回到项目里这两处：

- `setBook(Book& book)`：这里其实**不该**要写权限 —— 它只是把 `book` 抄进 `m_book`，一个字段都没改 `book`。严格说应该是 `setBook(const Book& book)`。项目里写的是 `Book&`，能跑，但限制了调用方（传 `const Book` 就报错）。
- `getBook()` 返回 `Book`（值，不是引用）：这是**故意的**，它返回的是一份副本，调用方改它改不到记录里的原件。代价是每次调用都复制一次。写成 `Book getBook() const` 更好（加 `const` 尾缀，见 Q8），但返回类型保持值是对的。

**加分一句**

"`const` 引用能绑到临时对象上，普通引用不能。所以 `void f(Book&)` 你写 `f(Book("书名", ...));` 会报错，而 `void f(const Book&)` 可以。这条规则叫'const 引用延长临时对象的生命周期'，是 C++ 里非常常用的一个便利。"

### Q5 给 `User` 加一个新的成员对象，会连带影响哪些地方？

**老师问什么**

"如果我现在让你给 `User` 加一个 `Date m_registerDate;`（注册日期）成员，你要改几个地方？"

**标准答案（可直接背）**

四个地方，一个都不能漏：

1. **`User.h` 的成员声明**：加 `Date m_registerDate;`。注意位置 —— 它会改变成员的声明顺序，从而改变构造和析构顺序。
2. **`User.h` 加 `#include "Date.h"`**：`User.h` 里出现了一个**完整的对象**（不是指针、不是引用），编译器必须知道 `Date` 有多大，所以必须 include 头文件。**这是组合和依赖在写法上最直观的差别**：组合要 `#include`，依赖只要前置声明（`class Book;`）就够。
3. **`User` 的构造函数初始化列表**：如果 `Date` 没有默认构造函数，你必须在这里显式构造它（`m_registerDate(...)`），否则报 `C2512`（第九节展开）。如果 `Date` 有默认构造，可以省略，但它照样会被默认构造一次。
4. **拷贝/赋值行为**：`User` 的默认拷贝构造函数和默认赋值运算符会自动连 `m_registerDate` 一起拷贝 —— 这部分不用你写，但你要**知道**它会自动做。如果 `Date` 里有指针成员，默认拷贝就是浅拷贝，那就必须自己写（第十课）。

**加分一句**

"加成员这种事，最容易被漏掉的是第 2 条：很多人只在 `.cpp` 里 `#include "Date.h"`，`User.h` 里没加，结果 `User.h` 一被别的文件包含就报一堆莫名其妙的错 —— 因为那个文件根本不知道 `Date` 是什么。**头文件里出现了完整类型（成员对象），就必须在头文件里 include，不能指望 `.cpp` 帮你兜。**"

### Q6 还书的时候，为什么不能只把 `m_borrownum` 减一？

**老师问什么**

"还书不就是'他少了一本书'吗？`m_borrownum--` 一下不就行了，为什么还要动数组？"

**标准答案（可直接背）**

因为 `m_borrownum` 同时承担两个含义：**"借了几本"**和**"下一个空位在第几格"**。只在末尾增删时这两个含义相等；一旦从中间删，数量减了、位置没变，两个含义就分家了，后面新借的书会覆盖掉本该保留的记录（详见 7.4 节缺陷 2 的表）。

所以正确的还书要做三件事，顺序不能换：

1. **找到位置** `pos`（按 ISBN 在 `m_records[0..m_borrownum-1]` 里找）；
2. **前移压紧**：`for (int i = pos; i < m_borrownum - 1; i++) m_records[i] = m_records[i+1];`；
3. **计数减一，清尾巴**：`m_borrownum--; m_records[m_borrownum] = BorrowRecord();`。

**加分一句**

"这套'找位置 → 前移 → 减计数'的操作，`std::vector` 的 `erase()` 内部做的是一模一样的事（一次 `erase` 是 O(n) 的原因就在这儿）。第五课学了 `vector` 之后，你可以把 `m_records` 换成 `vector<BorrowRecord>`，还书就变成一行 `m_records.erase(m_records.begin() + pos);` —— 但前提是你要先**理解**它内部为什么必须搬数据，不然用 `vector` 也只是把问题藏起来。"

### Q7 为什么按 ISBN 认书，不按书名？

**老师问什么**

"`returnBook` 里你写的是 `getISBN() == book.getISBN()`，为什么不是 `getTitle() == book.getTitle()`？"

**标准答案（可直接背）**

因为**书名不唯一，ISBN 唯一**。两本不同的书可以同名（《C++ Primer》有第 5 版、第 6 版；不同出版社可以出同名书），按书名认会认错：他想还第 6 版，系统可能把第 5 版的记录删了。

ISBN 是国际标准书号，一本书一个号，全球唯一，天然适合当"身份证"。这也解释了为什么 `Book` 里要专门存一个 `m_ISBN` 字段 —— 它存在的唯一意义就是给别的模块当索引用。

**加分一句**

"这个字段在数据库里的说法叫'主键'。判断一个字段能不能当主键，就问三句话：**唯一吗？不为空吗？不会变吗？** ISBN 三条都满足。书名三条都不满足。以后你设计任何'查找'功能，都先找那个满足三条的字段，找不到就自己造一个（比如这里的 `m_id`）。"

### Q8 什么是 `const` 成员函数？为什么 `getter` 要加 `const` 尾缀？

**老师问什么**

"你的 `Book.h` 里 `double getPrice();` 后面为什么不写 `const`？写了会怎样？不写会怎样？"

**标准答案（可直接背）**

`const` 尾缀（`double getPrice() const;`）的意思是：**这个函数承诺不改对象里的任何成员。** 编译器会检查这句话是不是真的 —— 你在里面写 `m_price = 1;` 会直接报错。

三个后果：

1. **不写 `const`**：`const Book` 对象（或 `const Book&` 参数）**不能**调用它，报 `C2662`。也就是说你的 getter 对 const 对象完全不可用。
2. **写 `const`**：`const Book` 对象可以调用，普通对象也可以调用。适用范围只增不减。
3. **`const` 对象只能调 `const` 成员函数** —— 这是 const 正确性的传导：你承诺了不改，编译器就不许你调用任何"可能改"的函数。

所以规则是：**getter 一律加 `const`，setter 一律不加。** 你项目里所有 getter 都缺这个 `const` —— 现在能跑是因为你没写过 `const Book&` 参数；一旦开始写（比如 `void printBook(const Book& b) { cout << b.getTitle(); }`），立刻报 `C2662`（第九节第二条展开讲真实报错文本）。

**加分一句**

"`const` 尾缀修饰的是隐含的 `this` 指针 —— 加了 `const` 就等于把 `this` 从 `Book* const` 变成 `const Book* const`。所以严格说，`const` 成员函数里连 `this` 都是只读的，这才是它不能改成员的根本原因。同一个函数名，一个 const 版一个非 const 版，算重载，编译器按对象是不是 const 来选。"

---

### Q9 `BorrowRecord` 里存的那本 `Book`，和书库里那本是同一个对象吗？

**老师问什么**

"`m_records[0].getBook()` 拿到的 `Book`，是不是就是书库里的 `Book b`？我改 `m_records[0]` 里的书名，书库里那本会跟着变吗？"

**标准答案（可直接背）**

**不是同一个对象，不会跟着变。** `BorrowRecord` 里是 `Book m_book;` —— 一个**完整的真对象**，不是指针、不是引用。`setBook` 里那句 `m_book = book;` 是逐字段**拷贝赋值**，把书名、作者、价格、状态全部抄了一份。

所以记录表里躺的是那本书的**复印件**。改复印件，原件不动；改原件，复印件也不动。

验证这件事不需要撬开 `User` 的私有成员 —— `setBook` 里那句 `m_book = book;` 干的事，和下面这句 `Book copy = a;` 是**完全同一个操作**（编译器生成的逐字段拷贝赋值）。单独跑这段就够：

```cpp
#include <windows.h>
#include <iostream>
#include "Book.h"
using namespace std;

int main()
{
	SetConsoleOutputCP(65001);
	Book a("C++ Primer", "Stanley Lippman", "电子工业出版社", "9787121358579", "B001", 128.0, false);

	Book copy = a;              // 这就是 setBook 里那句 m_book = book 干的事
	a.setPrice(999.0);          // 改书库里那本

	cout << "书库里 a 的价格 = " << a.getPrice() << endl;
	cout << "副本里的价格     = " << copy.getPrice() << endl;
	return 0;
}
```

真跑出来的结果：

```
书库里 a 的价格 = 999
副本里的价格     = 128
```

两个数字不一样。原件涨到 999，复印件还停在 128 —— 这就是"记录里那份是复印件，不是那本书本身"的铁证。

**这个设计的好处**：记录能长期保存"借出那一刻"的快照（当时的价格、当时的书名），就算以后书库改了价，历史记录不会被篡改。

**这个设计的代价**：你要花内存（每借一本书就复制一整个 `Book`，含 5 个 `string`），而且**两份数据可能不一致** —— 这正是第七节缺陷 2 里"表里的书和手上的书是两批"能发生的根本原因。

**加分一句**

"如果想让记录'指向'书库里那本（改一处两边都变，还省内存），就得把 `Book m_book;` 改成 `Book* m_book;` 或 `Book& m_book;`。但那是**聚合**关系，代价是要自己管指针的生命周期（书被删了，指针就悬空）。**组合省心但费内存、要手动同步；聚合省内存但费心、要管生命周期。** 选哪个取决于你更怕哪件事 —— 我们这里怕的是悬空指针，所以选了拷贝。"

## 九、五个你一定会遇到的报错


先把五条摆成一张表，括号里是真实报错编号：

| 报错原文（节选） | 什么意思 | 怎么改 |
|---|---|---|
| `error C2664: "void passByRef(Book &)": 无法将参数 1 从"const Book"转换为"Book &"` | 你把一个只读对象传给了一个可能改它的参数 | 参数改成 `const Book&`，或者传一个非 const 的实参 |
| `error C2662: "double Book::getPrice(void)": 不能将"this"指针从"const Book"转换为"Book &"` | 在 const 对象上调了一个没标 `const` 的成员函数 | 给函数加 `const` 尾缀 |
| `error C2512: "Holder": 没有合适的默认构造函数可用` | 成员的类没有默认构造函数，而你没有在初始化列表里显式构造它 | 在初始化列表里补上 `m(v)`，或者给那个类加默认构造 |
| `error C2530: "r": 必须初始化引用` | 引用声明了却没绑定对象 | 声明时立刻绑定：`Book& r = b;` |
| `error LNK2019: 无法解析的外部符号 "public: void __cdecl User::returnBook(void)" ...` | 声明了、调用了，但没写实现（或者没把实现那个 `.cpp` 加进项目） | 补上函数体，或把 `User.cpp` 加进项目 |

下面逐条展开。

### 第 1 条：`C2664` —— const 对象传不进普通引用

**真实报错（在 `/W4`、`/std:c++17`、`/utf-8` 下用 `cl` 实测，全文照抄）**：

```
error C2664: “void passByRef(Book &)”: 无法将参数 1 从“const Book”转换为“Book &”
note: 转换丢失限定符
note: 参见“passByRef”的声明
note: 尝试匹配参数列表“(const Book)”时
```

**触发的代码**：

```cpp
void passByRef(Book& b) { b.setPrice(1.0); }

void f(const Book& cb)
{
	passByRef(cb);      // ← 报 C2664
}
```

**为什么**：`const Book&` 承诺了"我不会改这个对象"，可 `passByRef` 的参数是 `Book&`，它有权改。如果让这个调用通过，那 const 承诺就形同虚设 —— 编译器必须拦住。

**怎么改**，两个方向选一个：

```cpp
// 方向一：让函数遵守 const（推荐，如果函数本来就不该改）
void passByRef(const Book& b) { cout << b.getPrice() << endl; }

// 方向二：让调用方拿一个能改的对象
Book b(...);
passByRef(b);
```

**你会在哪遇到**：写 `void printBook(const Book& b)` 之后，里面调 `b.getTitle()` —— 如果 `getTitle()` 没标 `const`，报的是下面的 `C2662`，不是这条。这条通常出现在"我想在 const 函数里调用会改对象的东西"。

### 第 2 条：`C2662` —— 在 const 对象上调了非 const 成员函数

**真实报错**：

```
error C2662: “double Book::getPrice(void)”: 不能将“this”指针从“const Book”转换为“Book &”
note: 转换丢失限定符
Book.h(28): note: 参见“Book::getPrice”的声明
note: 尝试匹配参数列表“()”时
```

**触发的代码**（这就是你项目里加了 `const` 参数之后立刻会撞上的那条）：

```cpp
void printPrice(const Book& b)
{
	cout << b.getPrice() << endl;   // ← 报 C2662，因为 Book.h 第 28 行 getPrice() 没标 const
}
```

**为什么**：`b` 是 const 对象，它的 `this` 类型是 `const Book*`。`getPrice()` 没标 `const`，它的 `this` 类型是 `Book*`（能改的）。把"能改的指针"从"只读的对象"上取下来，编译器不许。

**注意后面还会跟着一条连带错误。** 如果你写的是 `cout << b.getPrice()`（上面那段就是），C2662 之后立刻还有一条：

```
error C2088: 内置运算符 '<<' 无法应用于类型为 'std::ostream' 的操作数
```

这是**连锁反应**，不是第二个独立问题：`b.getPrice()` 那一句已经废了，`cout << (...)` 拿不到 `double`，`<<` 自然匹配不上。**只看第一条**，把 `const` 补上，C2088 会自己消失。

新手最容易在这条上跑偏的地方：C2088 的报错文本里出现了 `std::ostream`，于是有人跑去改 `#include <iostream>`、改 `using namespace std;`、甚至怀疑编译器坏了 —— 全都是白忙。**报错要从第一条往下读，第一条才是根因。**

**怎么改**：给 `Book.h` 里的 getter 加 `const` 尾缀（这一条要改 7 个 getter，一次性全改）：

```cpp
	string getTitle() const;
	string getAuthor() const;
	string getPublisher() const;
	string getISBN() const;
	string getId() const;
	double getPrice() const;
	bool getIsBorrowed() const;
```

对应的 `Book.cpp` 里，实现部分也要跟着加 `const`：

```cpp
double Book::getPrice() const
{
	return m_price;
}
```

**注意**：声明和实现的 `const` 必须**两边都写**。只改 `.h` 不改 `.cpp`，编译器认为是两个不同的函数，报 `LNK2019`（找不到 `getPrice() const` 的定义）—— 只有声明没实现，正好撞上下面第 5 条。

### 第 3 条：`C2512` / `C2280` —— 成员没有默认构造函数

这条要分两种场景说，因为**报错编号不一样**，很多人以为是两个不同的错误。

**场景 A：你自己写了构造函数但没在初始化列表里构造成员。**

**真实报错**：

```
error C2512: “Holder”: 没有合适的默认构造函数可用
note: 参见“Holder”的声明
```

**触发的代码**：

```cpp
struct Item
{
	Item(int v) : x(v) {}        // 有带参构造，默认构造被"挤掉"了
	int x;
};

struct Holder
{
	Item m;
	Holder(int v) : m(v) {}      // 这个是对的
};

int main()
{
	Holder h;                    // ← 报 C2512：需要 Holder 的默认构造，但它要求传 v
	return 0;
}
```

看清楚：`C2512` 报的是 **`Holder`** 没有默认构造函数，不是 `Item`。因为 `Holder h;` 要求一个能无参调用的 `Holder` 构造函数，而 `Holder` 只写了一个要 `v` 的。

**怎么改**：

```cpp
	// 改法一：给它一个默认构造函数
	Holder() : m(0) { }
	// 改法二：不要无参构造
	Holder h(1);
```

**场景 B：`Holder` 完全没写构造函数。**

**真实报错**：

```
error C2280: “Holder::Holder(void)”: 尝试引用已删除的函数
note: 编译器已在此处生成“Holder::Holder”
note: “Holder::Holder(void)”: 由于 数据成员“Holder::m”不具备相应的 默认构造函数 或重载解决不明确，因此已隐式删除函数
```

**触发的代码**：

```cpp
struct Holder
{
	Item m;      // Item 没有默认构造函数
};               // Holder 一个构造函数都没写

int main()
{
	Holder h;    // ← 报 C2280
	return 0;
}
```

**为什么两个编号不一样**：`Holder` 自己没写构造函数时，编译器会"尽力"给你合成一个（`= default`）。但它检查成员时发现 `Item` 没默认构造，合成的那个没法实现，于是把它标成 **`= delete`**（已删除）。你用到它 → 报"尝试引用已删除的函数" = `C2280`。而场景 A 里你自己写了构造函数，编译器就不合成了，于是报"没有合适的默认构造函数" = `C2512`。

**怎么改**：给 `Item` 加一个默认构造函数，或者让 `Holder` 的构造函数显式初始化 `m`。

```cpp
struct Item
{
	Item() : x(0) { }            // 补一个默认构造
	Item(int v) : x(v) { }
	int x;
};
```

**你会在哪遇到**：给 `Book` 加一个新的成员对象（Q5 那种情况），如果那个类没有默认构造函数，`Book` 的默认构造函数立刻编译不过。项目里 `Book::Book()` 是手写的，它必须能构造 `m_title` 等全部成员；一旦加了需要参数的新成员，`Book()` 就要跟着改初始化列表。

### 第 4 条：`C2530` —— 引用声明了却没绑定

**真实报错**：

```
error C2530: “r”: 必须初始化引用
```

**触发的代码**：

```cpp
	Book& r;           // ← 报 C2530。以为"先声明，后面再赋值"
	r = someBook;
```

**为什么**：引用不是"一个可以后填的变量"，它从出生那一刻起就必须绑在一个已存在的对象上，而且**一辈子不能改绑**。所以"先声明后赋值"这条路根本不存在，语法上就堵死了。

**怎么改**：

```cpp
	Book& r = someBook;      // 声明的同时绑定
```

**顺带一个陷阱**（同一个 `C2530` 的变种）：

```cpp
	Book& r;                    // C2530，编译到这一行就停
	if (x) r = a; else r = b;   // 就算上面过了编译，这句也不是"改绑"，是把 a 或 b 的内容赋给 r 绑定的那个对象
```

**正确写法用指针**：

```cpp
	Book* p = (x ? &a : &b);    // 指针可以后赋、可以改指
```

**你会在哪遇到**：想写 `Book& r;` 然后根据条件绑不同对象 —— 这个需求只能用指针。引用只在"确定绑谁、只绑一次"时用。

### 第 5 条：`LNK2019` —— 声明了、调用了，就是没有实现

**真实报错**：

```
e5_LNK2019.obj : error LNK2019: 无法解析的外部符号 "public: void __cdecl User::returnBook(void)" (?returnBook@User@@QEAAXXZ)，函数 main 中引用了该符号
e5_LNK2019.exe : fatal error LNK1120: 1 个无法解析的外部命令
```

**注意这条报的是 `LNK` 不是 `C`** —— 它是**链接器**报的，不是编译器。含义完全不同：编译阶段每个 `.cpp` 单独过一遍，编译器只检查"这个名字我用得对不对、类型对不对"，它不管这个名字在别处有没有实现。等所有 `.obj` 交给链接器拼成 `.exe` 时，链接器发现"`User::returnBook` 有人要、没人给"，才报 `LNK2019`。

**触发的三种情况**（都会报这一条）：

1. **`User.h` 里声明了，`User.cpp` 里没写实现**：
   ```cpp
   // User.h
   void returnBook(Book& book);
   // User.cpp —— 完全没写 User::returnBook 的函数体
   ```
2. **写了实现，但实现时把类名漏了**（写成全局函数）：
   ```cpp
   void returnBook(Book& book) { ... }        // ← 漏了 User::
   // 这是全局函数，不是 User 的成员，链接器找不到 User::returnBook
   ```
3. **`User.cpp` 没被加进项目**：`User.cpp` 文件在磁盘上，但没在"解决方案资源管理器"里，编译时它根本没参与，自然没有 `.obj`。

**怎么改**：

- 情况 1：把函数体补上。
- 情况 2：改成 `void User::returnBook(Book& book) { ... }`。
- 情况 3：右键项目 → 添加 → 现有项 → 选 `User.cpp`。（或者把实现直接写进 `User.h` 里，那就成了内联，不需要 `.cpp`。）

**看懂那个乱码一样的修饰名**：`?returnBook@User@@QEAAXXZ` 是 MSVC 的"修饰名"（mangled name），里面 `@User@` 说明它属于 `User` 类，`QEAA` 编码了调用约定，`XXZ` 里的 `X` 表示 `void` 返回值、`X` 表示 `void` 参数。**看到 `@类名@` 就直接去那个类里找函数体有没有写。**

### 任务 A　把 `Book` 塞进 `Student` 里（组合入门）

**要你做什么**

1. 写一个 `StudentA` 类，三个成员：`string m_name`、`string m_id`、`Book m_borrowed`。
2. 提供两个构造函数：
   - 默认构造 —— 造出一个空学生（姓名学号空、书是空书）。
   - 带参构造 `StudentA(string name, string id, const Book& b)` —— 用传进来的书**初始化我的成员**。

**提示（不剧透）**

- 第 3 步那句"用传进来的书初始化我的成员"，位置在**初始化列表**里，不在花括号里。想一想 6.3 第三条：`Book` 如果有带参构造而没有默认构造，写进花括号里根本编不过。
- 第 4 步是这道题的**全部意义**。你改 `a1` 之后 `stuA` 里那本变不变，就是"组合"这个词的定义。
- `display()` 标 `const` 之后，里面能调的方法也必须是 `const` 的。如果 `Book::display()` 还没加 `const` 尾缀，这里会报 C2662 —— 回去把 5.5 的清单做完。

class StudentA

    string m_name;

    }

### 任务 B　借书 / 还书，参数传指针（依赖入门）

**要你做什么**

写一个 `StudentB` 类，里面存**一本**书（还是 `Book m_borrowed`），再写两个成员函数：

```cpp
bool borrowBook(Book* b);       // 借书
bool returnBook(Book* b);       // 还书
```

要求：

1. `borrowBook` 成功时返回 `true`，失败返回 `false`，**失败必须打印一句人能看懂的原因**。
2. 要挡住四种情况：
   - 传进来的是 `nullptr`；
   - 我手上已经借了别的书（还没还）；
   - 这本书已经被别人借走了；
   - （已经借到手的情况下）再借同一本。
3. `returnBook` 要挡住两种情况：传进来是 `nullptr`；要还的书**不是他借的那本**。
4. `main` 里逐个跑这些场景，每个场景前先 `cout` 一句"这一条应该成功/失败"，然后对照输出。
5. 最后做一个对比：写一个 `void borrowByValue(Book b)` 和一个 `void borrowByPointer(Book* b)`，都在里面调 `setIsBorrowed(true)`，各自打印形参地址，让 `main` 里那本书的真实状态说话。

**提示（不剧透）**
