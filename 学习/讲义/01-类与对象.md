## 一、先搞清楚：代码是怎么变成程序的

这是零基础最大的空洞。你不理解它，后面所有报错你都不知道它在说什么。

你写的 `.cpp` 是**文本**，人看的。CPU 看不懂 `cout << "hi"`。中间要经过三步：

```
Book.h ──┐
Book.cpp ┼──► 编译(compile) ──► 目标文件 .obj ──► 链接(link) ──► LibrarySys.exe
main.cpp ┘        ↑ 每个 .cpp 单独编译            ↑ 把 .obj 拼起来
```

**编译**：一个 `.cpp` 单独翻译成机器码，存成 `.obj`。这一步检查语法 —— 少个分号、类型不对，都是在这一步骂你。

**链接**：把所有 `.obj` 和用到的库拼成一个 `.exe`。这一步检查"你声明了的东西到底有没有实现" —— 比如你在 `.h` 里写了 `void display();`，但 `.cpp` 里忘了写函数体，编译过得去，链接会报 `unresolved external symbol`。

> **记住这个区别，它决定了你看报错的方式**：
> - `error Cxxxx` → 编译错误，语法/类型问题，看行号去改那一行
> - `error LNKxxxx` → 链接错误，声明了没实现，或者没把某个 `.cpp` 加进项目

### 为什么分 `.h` 和 `.cpp` 两个文件

这是 C++ 的规矩，不是多余。

- **`.h`（头文件）= 菜单**：告诉别的文件"我这个类叫什么、有哪些成员、能调哪些函数"。只有**声明**，没有实现。
- **`.cpp`（源文件）= 后厨**：真正写函数体。

谁要用 `Book`，就 `#include "Book.h"` 把菜单拿过去。编译器看到菜单就知道 `Book` 是个什么类型、有没有 `getTitle()`，但它不需要知道 `getTitle()` 怎么写的 —— 那是链接阶段的事。

好处：改了 `Book.cpp` 的实现，所有 `#include "Book.h"` 的文件不用重新编译。这在几百个文件的项目里是天壤之别。

你项目里就是这样组织的：

| 文件 | 内容 |
|------|------|
| `Book.h` | `class Book` 的声明：成员变量 + 函数名 |
| `Book.cpp` | 每个函数的实现：`Book::getTitle() { return m_title; }` |
| `LibrarySys.cpp` | 只有一个 `main()`，程序入口 |

### `main()` 是什么

```cpp
int main()
{
    // 从这里开始，一行一行往下跑
    return 0;   // 0 = 正常结束
}
```

程序启动 → 操作系统找到 `main` → 从 `main` 第一行往下执行 → `return 0` 或跑到末尾 → 程序结束。

一个程序**有且只有一个** `main`。所以 `Book.cpp` 里没有 `main`，`User.cpp` 里也没有 —— 都在 `LibrarySys.cpp` 里。

### `#pragma once` 和 `using namespace std;`

```cpp
#pragma once        // 这个头文件只被包含一次（防止重复包含导致"重复定义"报错）
#include <string>   // 我需要用到 string 类型
using namespace std;  // 后面不用写 std::string，直接写 string
```

`using namespace std;` 的意思是"std 这个名字空间里的东西我直接拿来用" —— 所以能写 `string` 而不是 `std::string`、`cout` 而不是 `std::cout`。教材上不推荐在头文件里这么写（会造成命名空间污染），但你的作业里这么写完全没问题，老师也不会扣分。

## 二、类型与变量：数据在内存里长什么样

变量 = 一块内存 + 一个名字 + 一个类型。**类型决定了这块内存多大、能放什么、能做什么运算**。

你作业里只用得到这几个：

| 类型 | 装什么 | 占多大 | 写法 |
|------|--------|--------|------|
| `int` | 整数 | 4 字节 | `int m_pages = 320;` |
| `double` | 小数 | 8 字节 | `double m_price = 128.0;` |
| `bool` | 真/假 | 1 字节 | `bool m_isBorrowed = false;` |
| `string` | 一串字符 | 不定 | `string m_title = "C++ Primer";` |
| `char` | 单个字符 | 1 字节 | `char c = 'A';` |

`int` 和 `double` 千万不能混：
```cpp
int a = 10 / 3;        // a = 3    （整数除法，小数部分直接扔掉）
double b = 10 / 3;     // b = 3    （先算整数除法得 3，再变 3.0）
double c = 10.0 / 3;   // c = 3.333...  ← 想要小数就得有一个是小数
```

### `string` 的特别注意

`string` 是"类"不是"基本类型"，所以：

```cpp
string a = "abc";
string b = "def";
string c = a + b;          // c = "abcdef"   —— string 定义了 + 号的行为（运算符重载）
int n = a.length();        // n = 3          —— 求长度，用 . 调用成员函数
bool eq = (a == "abc");    // eq = true      —— 直接 == 比较内容（不是比较地址）
```

这也顺便回答了一个很实用的技巧 —— `Lesson` 里那个 `cin >> value` 的坑，见第八节。

### 名字前的 `m_`

```cpp
string m_title;
double m_price;
```

`m_` 是 **m**ember 的缩写，表示"这是成员变量"。业界惯例，不是语法要求。好处：一眼能看出 `m_price` 是对象自己的数据，`price` 是函数参数。你的 `Book` 和 `User` 都用了这个前缀，保持一致。

## 三、函数：能重复用的那段逻辑

```cpp
double add(double a, double b)   // 返回类型  函数名(参数列表)
{
    return a + b;                // return 把结果交回去
}

// 用
double total = add(1.5, 2.5);    // total = 4.0
```

- **返回类型** `double`：函数算完交回什么类型。什么都不交就写 `void`。
- **参数**：传进来的东西，可以有多个、可以没有。
- **`return`**：交回结果并立刻结束函数。`void` 函数里也可以写 `return;` 单独一行表示提前结束。

你项目里的 `readInt`：

```cpp
int readInt(string tip)
{
    int value = 0;
    cout << tip;
    if (!(cin >> value))        // 读失败（比如用户输了字母）
    {
        cin.clear();            // 清掉错误标记
        cin.ignore(1024, '\n'); // 丢掉这行剩余内容
        cout << "输入格式不正确，请输入数字" << endl;
        return -1;              // 交回 -1 表示失败
    }
    cin.ignore(1024, '\n');     // 丢掉回车
    return value;
}
```

### 函数必须先声明才能用

`main` 里调用 `readInt`，编译器必须先知道 `readInt` 存在。你 `LibrarySys.cpp` 里 `readInt` 定义在 `main` 前面，所以能直接用。如果定义在后面，就得先在前面写一行声明：

```cpp
int readInt(string tip);   // 声明（只有长相，没有身体）
```

这就是 `.h` 文件的本质 —— 一堆声明。

### 值传递 vs 引用传递（**这是实验二的核心，现在先见一面**）

```cpp
void byValue(double x) { x = 999; }          // 传副本：改的是副本
void byRef(double& x)  { x = 999; }          // 传本体：改的是原来的

double p = 128.0;
byValue(p);   // p 还是 128.0
byRef(p);     // p 变成 999.0
```

`&` 在类型后面就是"引用"，意思是"这参数是外面那个变量本人，不是复制品"。

第 2 课会把这件事彻底讲透，现在你只需要记住：**函数里想改调用者的东西，就要加 `&`。**

## 四、类与对象：把数据和行为绑在一起

现在进正题。

```cpp
class Book
{
private:
    string m_title;
    double m_price;
    bool   m_isBorrowed;

public:
    void display() { ... }
};
```

- **`class`** 定义一个类型。这张是**图纸**，还没有占用任何数据。
- **对象**是用图纸造出来的实物：`Book b1;` 造了一个 `b1`，它有自己的 `m_title`、`m_price`。
  图纸一张，实物可以有无数个。
- **成员变量**（数据成员）：`m_title` 等，每个对象各有一份。
- **成员函数**：`display()` 等，**代码全程序只有一份**，所有对象共用，调用时知道该操作哪个对象的数据。

> 这句是考点，也是理解的关键：`b1.display()` 和 `b2.display()` 用的是同一段代码，但因为调用时"绑定"的对象不同，打印出来的是各自的数据。

### 用 `.` 和 `->`

```cpp
Book b1;              // 栈上的对象
b1.display();         // 用 .

Book* p = &b1;        // 指针指向 b1
p->display();         // 指针用 ->（等价于 (*p).display()）
```

现在只用 `.` 就够，指针在第 2、4 课再上。

## 五、`private` / `public`：封装到底在防谁

```cpp
class Book
{
private:              // 只有本类的成员函数能碰
    string m_title;
    double m_price;

public:               // 谁都能调
    string getTitle();
    void   setPrice(double price);
};
```

```cpp
Book b;
b.m_title = "乱写";      // ✗ 编译错误！private 成员，外面碰不到
b.setTitle("C++ Primer"); // ✓ 走 public 函数
```

**为什么要把数据私有？** 因为数据一旦公开，就没有任何东西能保证它是对的：

```cpp
// 数据 public 的话，谁都能这么干：
b.m_price = -999;        // 负数价格
b.m_isBorrowed = true;   // 明明在馆，被人改成"已借出"
```

**改成私有 + setter，你就有了一个检查点：**

```cpp
void Book::setPrice(double price)
{
    if (price < 0)
    {
        cout << "价格不能为负" << endl;
        return;              // 不合法就不改
    }
    m_price = price;
}
```

这就是**封装**：把数据藏起来，只留受控的通道。老师问"封装性指什么"，你就答这个。

> 实验一思考题第一题就是问这个。答案在第八节。

## 六、构造函数：对象出生时自动执行的那段代码

```cpp
class Book
{
public:
    Book();                                        // 构造函数 1：默认构造
    Book(string title, string author, ..., bool);  // 构造函数 2：带参构造
};
```

三条铁律：

1. **名字和类名完全相同**
2. **没有返回类型**（连 `void` 都不写）
3. **创建对象时自动被调用**，你不能手动调

```cpp
Book b1;                          // 自动走 Book()
Book b2("C++ Primer", ..., 128);  // 自动走 Book(...)
```

两个名字一样、参数不同 —— 这叫**重载**。编译器按你给的参数个数和类型自己挑。

### 为什么默认构造里要一个一个赋初值

```cpp
Book::Book()
{
    m_title = "";
    m_author = "";
    ...
    m_price = 0;
    m_isBorrowed = false;
}
```

因为 **`string` 不初始化会自动变成空串（安全），但 `double`、`int`、`bool` 不初始化就是内存里的垃圾值**。

```cpp
class Bad
{
public:
    int m_x;     // 没初始化
};

Bad b;
cout << b.m_x;   // 可能是 0，可能是 -858993460，可能是任何东西
```

这是 C++ 最经典的新手坑：看起来"有时能跑"，换台机器就炸。**规则：所有成员变量，构造函数里全部赋初值，一个不漏。** 你项目里的 `Book()` 和 `User()` 都做到了，保持这个习惯。

> 更现代的写法叫"初始化列表"：`Book::Book() : m_price(0), m_isBorrowed(false) {}`。第 2 课讲组合关系时必用（因为对象成员只能用初始化列表构造），现在先认识一下。

### 析构函数

```cpp
~Book() { ... }   // 名字是 ~类名，没有参数，对象销毁时自动调用
```

用来做清理（比如 `new` 出来的内存要 `delete`）。你现在 `Book` 里没有指针成员，不需要写析构函数 —— 编译器自动生成的那个就够了。第 4 课讲虚析构时会重点踩这个坑。

## 七、getter / setter 与 `display()`

```cpp
string Book::getTitle() { return m_title; }        // 取：返回成员的值
void Book::setTitle(string title) { m_title = title; }  // 存：把参数存进成员
```

为什么这个套路这么啰嗦还要写？

1. 数据私有后，外面只能通过这两个口子进出 —— **你随时能在 setter 里加校验**
2. 将来改了内部存储方式（比如 `m_price` 从 `double` 改成 `int` 存分），只要 getter 的返回类型不变，所有调用方一行都不用改
3. 可以只给 getter 不给 setter，这个成员就变成**只读**

`display()` 就是个普通成员函数，只是做输出：

```cpp
void Book::display()
{
    cout << "Title: " << m_title << endl;
    cout << "Price: " << m_price << endl;
}
```

`cout <<` 后面可以连一长串，`endl` 是换行（`\n`）并刷新缓冲区。`cout` 会自动按类型转成文字 —— 所以 `double` 会打成 `128`，`bool` 会打成 `1/0`（想打"真/假"要自己用 if 转）。

> 你现在的 `Book::display()` 第 110-113 行有个**没写完的 if**：
> ```cpp
> if (m_isBorrowed)
> {
>     //（视频中未完成：此处可输出"已借出"状态）
> }
> ```
> 这是实验一的第一个待补点，见下面的任务 B。

## 八、实验一的思考题（老师会问）

**Q：访问控制的好处在于什么？为什么类定义里要考虑访问控制？封装性是指什么？**

> 答：访问控制把"数据"和"使用数据的方式"分开。私有成员只能通过公开函数访问，于是所有修改都经过同一个入口，我可以在入口里做校验（价格不能为负、借出数量不能超上限），保证对象永远处于合法状态。如果不加控制，任何代码都能直接改成员，对象状态就无从保证。
> 封装性 = 把数据和操作数据的方法捆绑在类里，并对外隐藏实现细节，只暴露必要接口。它的价值是：内部怎么改都不影响外部调用方，降低耦合。

**Q：对象什么时候产生、什么时候消亡？作用域和生命周期有什么关系？**

> 答：局部对象在**执行到它的定义语句时**由构造函数创建，在**离开它所在的花括号 `{}`** 时由析构函数销毁。作用域决定了这个对象在哪些代码里能被看见和使用，生命周期决定它实际存在多久 —— 对普通局部对象来说两者一致；但用 `new` 创建的对象作用域可能只是那个指针变量，生命周期却延续到 `delete` 为止。

## 九、五个你一定会遇到的报错

| 报错 | 意思 | 怎么改 |
|------|------|--------|
| `error C2143: 语法错误: 缺少";"` | 少分号/括号不配对 | 看它指的行号**上一行**的行尾 |
| `error C2065: "xxx": 未声明的标识符` | 名字打错了，或者没 `#include` 对应头文件 | 检查拼写、检查 include |
| `error C2084: 函数已有主体` | 同一个函数实现了两次（比如 `.cpp` 里写了两遍） | 删掉重复的 |
| `error LNK2019: 无法解析的外部符号` | 声明了但没实现，或 `.cpp` 没加进项目 | 补函数体 / 检查项目文件列表 |
| `error C2679: 二进制"<<": 没有找到接受...` | `<<` 后面的类型不对，或者忘了 `#include <string>` | 检查类型 |

**看报错的正确姿势**：从上往下找**第一个** `error`，后面的通常是被它带出来的假错误。改完第一个，重新编译，再看下一个。

### 任务 C（进阶，也是实验一真正要求的）—— ISBN 合法性校验

作业原文：「其他操作：验证图书 isbn 号的合法性」。

ISBN-13 的规则：**13 位数字**，且前 12 位按权重 1、3、1、3… 交替相乘求和后，用 `10 - (和 % 10)` 得到校验位（若结果是 10 则取 0），要和第 13 位相等。

```
ISBN-13 示例: 978-7-121-35857-9   → 9787121358579
前 12 位: 9 7 8 7 1 2 1 3 5 8 5 7
权重:     1 3 1 3 1 3 1 3 1 3 1 3
乘积和:   9+21+8+21+1+6+1+9+5+24+5+21 = 131
131 % 10 = 1  →  10 - 1 = 9  →  校验位是 9，和末位 9 一致 ✓
```

把这个写成 `BookCard` 的成员函数：

```cpp
bool isValidISBN();    // ISBN 合法返回 true
```

需要的工具（现在只要会认，不要求背）：
- `m_isbn.length()` 求长度
- `m_isbn[i]` 取第 i 个字符（`i` 从 0 开始）
- `m_isbn[i] - '0'` 把字符 `'9'` 变成数字 `9`
- `m_isbn[i] >= '0' && m_isbn[i] <= '9'` 判断是不是数字

先自己写，卡住了再来问。这个函数写出来，实验一的"其他操作"就齐了，你可以直接把它搬回项目的 `Book` 类。
