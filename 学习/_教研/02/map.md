# 第二章 组合与依赖 · 开篇导读

这一章只解决一件事：**你改了一个对象，另一个地方怎么知道。**

十节内容看着多，其实是同一条链子上的十环。先看地图，知道自己在哪；再看三分钟自测，知道自己缺哪一环。

---

## 本章知识地图

```
                        一 个 现 象
        借了跟没借一样：borrow(Book b) 里明明改了，
        回到 main，书还是"可借"。
                                |
                                |  为什么改不动？
                                v
                        三 个 工 具
        给函数传一个对象，有三种传法，效果完全不同。

        值传递      Book  b            第二节
          拷一份复印件进来。改复印件，原件纹丝不动。

        引用        Book& b            第三节
          不拷贝，直接绑住外面那个对象。改的就是原件。

        指针        Book* b            第四节
          递一个门牌号进去，顺着门牌号找到原件再改。

        只读版      const Book& b      第五节
          不拷贝，但也不许改。专给"只看不改"的函数用。
                                |
                                |  工具有了，对象之间怎么搭？
                                v
                        两 个 关 系

        组合        第六节
          User 里真的有一个 BorrowRecord，里面又真的有一个 Book。
          人一出生，里面的记录就跟着出生；人一销毁，记录跟着销毁。
          这是"拥有"。注意：拥有的是副本，不是书库里那本书本身。

        依赖        第七节
          借书函数的参数 Book& book。调用时把书借进来，函数一返回就还回去。
          这是"用一下"，不拥有。
                                |
                                |  前面所有东西，最后都指向同一句话
                                v
                        一 个 纪 律
        借阅成功 = 书变"已借出" + 人计数加一 + 记录里多一条。
                   两 边 都 变，只变一边就是 bug。
                                |
                                v
         第八节 自测  ——  第九节 排错  ——  第十节 动手
```

一句话读法：**现象在第一节，工具在二到五节，关系在六七节，纪律在七八十节。**

## 三分钟自测

10 道题：判断 6 道，填空 4 道（共 8 个空）。合上讲义做，做完一次性对答案。

**判断（对或错）**

1. `void borrow(Book b)` 里把 `b` 的状态改成"已借出"，函数返回后，`main` 里传进去的那本书也是"已借出"。

2. 调用 `void borrow(Book b)` 会创建一本新书；调用 `void borrow(Book& b)` 不会创建任何新书。

3. `void f(Book& b)` 里的 `&` 表示＿＿＿＿；`&book` 里的 `&` 表示＿＿＿＿。

4. 参数写成 `const Book& b`，既能避免复制一整本书，又能保证函数里改不了 `b`。

5. `bool getIsBorrowed() const` 末尾那个 `const` 表示＿＿＿＿；去掉它以后，一个 `const Book&` 就＿＿＿＿这个函数。

6. `User` 对象被创建时，它内部的 `BorrowRecord`、以及 `BorrowRecord` 内部的那个 `Book`，都会自动跟着被构造出来，不用你手写代码。

7. `BorrowRecord` 里的 `Book m_book;`，存的就是书库里那本书本身；改它，书库里那本书也跟着变。

8. 手里是 `Book* p` 时，调用 `getTitle()` 写成 `p＿＿＿＿getTitle()`；手里是 `Book& r` 时，写成 `r＿＿＿＿getTitle()`。

9. 还书时只把借阅计数减一就够了，不用检查"他还的这本是不是他借过的那一本"。

10. 一次借书要成功，必须同时满足两个条件：这本书是＿＿＿＿状态，这个人的已借数量＿＿＿＿。

<details><summary>答案</summary>

1. **错。** 函数里改的是形参 `b`，它是 `book` 的副本，两者地址不同。函数一返回，副本连同改动一起消失。

2. **对。** `Book b` 要造新对象，走拷贝构造函数；`Book& b` 只是给外面那个对象多起一个名字，不产生任何新对象。

3. **引用声明 / 取地址。** 同一个 `&`，写在类型后面是"我声明一个引用"，写在变量前面是"把这个变量的地址取出来"。两处含义互不相干。

4. **对。** `&` 管住"不拷贝"，`const` 管住"不许改"。两件事一次办完，所以它出现频率高得离谱。

5. **这个函数不修改任何成员变量 / 就调不动它（编译报错）。** 一个 `const Book&` 只肯调用带 `const` 尾缀的成员函数，这是编译器帮你守的规矩。

6. **对。** 成员对象的构造是自动的，顺序按它们在类里的声明顺序来，跟初始化列表里写的先后无关。

7. **错。** `Book m_book;` 是一个真真切切的 `Book` 对象，赋值时走的是拷贝。它和书库里那本书是两个独立对象，改一个另一个不知道。

8. **`->` / `.`** 左边是指针用 `->`，左边是对象或引用用 `.`。

9. **错。** 不校验的话，还一本压根没借过的书也会"还成功"，计数和记录当场对不上。你项目 `User.cpp:97` 的 `returnBook` 就是这个毛病。

10. **可借（`m_isBorrowed == false`） / 没借满（`m_borrownum < m_maxnum`）。** 两条都成立才借。只满足一条就不给借，并且明确告诉对方是哪一条不满足。

</details>
