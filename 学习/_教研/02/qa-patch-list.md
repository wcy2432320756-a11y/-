原文说"MSVC 没有对应的默认警告、`/W4` 一声不吭"。这句不完整。二次实测（`cl /W3` / `/W4` / `/Wall`）：

## 一、事实类

**1. `[P0]` [§6.2] 编造的编译器警告 C5038 —— `part3.md:435-441`（警告文本在 438 行）**
锚点：`这条 warning 不是唠叨，它在告诉你`
原文称 MSVC 在初始化列表顺序与声明顺序不一致时会报 `warning C5038: 数据成员"Owner::m_b"将先于数据成员"Owner::m_a"初始化`，并说"`/W3` 就会出"。本机实测三次（`/W3`、`/W4`、`/W4 /permissive- /std:c++20`，VS 18 Community），**全部零警告**，只回一个文件名，`t.obj` 正常生成。改成反向表述："编译器会提醒你吗？不会" —— GCC / Clang 有 `-Wreorder`（`-Wall` 里带着），MSVC 没有对应的默认警告，`/W4` 实测一声不吭，直接按声明顺序构造。同时删掉「这条 warning 不是唠叨，它在告诉你"你以为的顺序和实际的顺序不一样"。看到它就说明你列表写反了。」这两句。

**2. `[P0]` [§6.2] 补上这条规则真正会炸的场景（与第 1 条同一处改）**
锚点：紧跟第 1 条，写成"编译器不救你"之后的下一段。
原文只演示"列表写反、各用各的常量"，那种情况写反了结果一样，学生看不出危害。补一个会崩的写法：`class Danger { Part m_a; Part m_b; public: Danger() : m_b("b"), m_a(m_b.tag().c_str()) {} };` —— 意图是让 `m_b` 先造好再给 `m_a` 用，但实际按声明顺序 `m_a` 先造，于是 `m_a` 的构造参数读的是一个**还没构造的 `m_b`**。本机实测：编译零警告，运行在构造 `m_a` 那一刻直接崩，退出码 `0xC0000409`，连第一行输出都没打出来，连跑 4 次 4 次崩。落一句结论：成员永远按声明顺序构造，想要"先造谁"只能改声明顺序。

**3. `[P0]` [全章] 两套 `Book` 签名从来没有交代过 —— `part1.md` 全节 + `part3.md:565`**
锚点：`Book` 唯一的构造函数要求七个参数
练习代码里的 `Book` 是精简版：3 个 `string` + `double` + `bool`，带参构造 **4 个参数** `Book(string title, string author, string isbn, double price)`，ISBN 的 getter 叫 `getIsbn()`（小写 s）。项目里的 `Book` 是 5 个 `string` + `double` + `bool`，带参构造 **7 个参数**（`Book.h:19-21`），getter 叫 `getISBN()`（全大写）。全章只有 `part2.md:151` 一行**代码注释**带过（`// 112 —— 我的简化版 Book（3 个 string），你项目那个会更大`），正文从没说构造签名和 getter 名字不同。最刺眼的矛盾就在 `part3.md:565`：那里写「`Book` 唯一的构造函数要求七个参数」（项目版），而同一章 `part3.md:715`、任务 A 的 `part1` 系示例都用 4 个参数。改法：在第一次出现 `Book` 构造之前（`part1.md:38` 之前）插一张"两套 Book"对照表，四行即可 —— 字段数（3 string vs 5 string）、带参构造参数个数（4 vs 7）、ISBN getter（`getIsbn()` vs `getISBN()`）、有无所属 `publisher` / `id` 字段。再把 `part4.md` 的 §7.1「本章有两套名字」表升级成全书唯一基准，其它地方一律指回它。
